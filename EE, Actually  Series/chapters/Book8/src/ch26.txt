H1: Chapter 26. HDL: Software That Becomes Hardware
P: Twenty lines of text describe a PWM generator. Run them through a C compiler and you get an error. Run them through a synthesis tool and you get flip-flops and gates, wired together on an FPGA board that typically costs about $20, producing a 105.5 kHz waveform with no CPU, no interrupts, and no jitter. Send a slightly larger text file to a shared shuttle, and some months later it comes back as silicon. A hardware description language looks like a programming language, but every line describes a circuit that exists all the time and does everything at once. Thinking of it as software that runs from top to bottom is the most common way to get it wrong.
P: Where you meet this: FPGA prototyping and products (camera interfaces, motor control, software-defined radio, test equipment), chip design at every scale, and the hobby route from an LED blinker to a self-designed chip.
H2: 26.1 Describing hardware
P: Verilog and its successor SystemVerilog are the HDLs most used for chip design; VHDL remains common in aerospace and in some European design flows. A module has ports, like a function's parameters, but its body describes circuits. An always block triggered by posedge clk describes flip-flops: every register in it takes its new value at the same clock edge, which is why such blocks use the nonblocking assignment <=. A continuous assign or an always @* block describes combinational logic, gates whose outputs follow their inputs. Everything in a module runs in parallel, all the time; the order of the blocks in the file means nothing to the hardware. Width is explicit: reg [7:0] is an 8-bit register, and arithmetic wraps at that width, which the PWM counter below uses on purpose. The logic gates and flip-flops themselves are Book 1's.
P: Listing 26.1 — An 8-bit PWM generator: a free-running counter, a compare, and a registered output (Verilog).
P: `timescale 1ns/1ps// 8-bit PWM: the output is high while the free-running counter is below the duty value.// At 27 MHz (Tang Nano 9K) the period is 256 clocks = 9.48 us, i.e. 105.5 kHz.module pwm #(    parameter WIDTH = 8) (    input  wire             clk,    input  wire             rst_n,     // active-low reset    input  wire [WIDTH-1:0] duty,      // 0 = always off, 255 = on for 255 of 256 clocks    output reg              out);    reg [WIDTH-1:0] count;    always @(posedge clk or negedge rst_n) begin        if (!rst_n) begin            count <= {WIDTH{1'b0}};            out   <= 1'b0;        end else begin            count <= count + 1'b1;               // wraps from 255 to 0            out   <= (count < duty);             // registered output: no glitches        end    endendmodule
H2: 26.2 Simulation and testbenches
P: Hardware is tested in simulation before it is built. A testbench is a Verilog module with no ports: it generates the clock, applies inputs, checks outputs, and reports. It may use constructs that cannot become hardware, such as delays (#18.518), loops over time, $display, and file output, because it only ever runs in the simulator. Icarus Verilog (iverilog) is a free event-driven simulator; Verilator compiles the design into fast C++ and is also an excellent linter; both write VCD waveform files that GTKWave or Surfer display. The testbench is step 5 of the method for hardware, and because a bug found after manufacturing cannot be patched, it is a much larger part of the work than in firmware.
P: Listing 26.2 — A self-checking testbench: it counts high clocks over whole periods for five duty values and reports failures (Verilog, Icarus).
P: // Testbench: measure the PWM duty cycle over whole periods and compare with the setting.`timescale 1ns/1psmodule pwm_tb;    reg clk = 0, rst_n = 0;    reg [7:0] duty;    wire out;    integer high, i, errors = 0;    pwm #(.WIDTH(8)) dut (.clk(clk), .rst_n(rst_n), .duty(duty), .out(out));    always #18.518 clk = ~clk;                   // 27 MHz: period 37.037 ns    task check(input [7:0] d);        begin            duty = d;            repeat (256) @(posedge clk);         // let the new value take effect            high = 0;            for (i = 0; i < 256; i = i + 1) begin                @(posedge clk);                high = high + out;            end            if (high !== d) begin                errors = errors + 1;                $display("FAIL duty %0d: %0d of 256 clocks high", d, high);            end else                $display("ok   duty %3d: %3d of 256 clocks high (%.1f %%)", d, high, 100.0 * high / 256);        end    endtask    initial begin        $dumpfile("pwm.vcd");        $dumpvars(0, pwm_tb);        duty = 0;        #100 rst_n = 1;        check(0); check(1); check(64); check(128); check(255);        $display("%0d errors", errors);        $finish;    endendmodule
H2: Worked Example 26.1: The PWM on a Tang Nano 9K
P: Problem. The Tang Nano 9K has a 27 MHz oscillator. Find the PWM frequency of the 8-bit generator, the duty resolution, and the shortest pulse, and check them in simulation.
P: Solution. The counter wraps every 256 clocks: 27 MHz/256 = 105.47 kHz, a period of 9.48 µs. Duty steps are 1/256 = 0.39 %, and the shortest pulse is one clock, 37.0 ns. Duty 255 gives 255 of 256 clocks, 99.6 %; a full 100 % would need a ninth bit or a special case. The testbench of Listing 26.2 measured exactly 0, 1, 64, 128, and 255 high clocks per period for the five settings, 0 errors, in Icarus Verilog 12, and Verilator's lint with all warnings enabled reported nothing. Compare Chapter 7's ESP32-S3 LEDC: the same arithmetic with a hardware timer, but here the timer is something you wrote.

P: Listing 26.3 — A UART transmitter for 8N1 with a clock divider parameter: start bit, eight data bits LSB first, stop bit (Verilog).
P: `timescale 1ns/1ps// UART transmitter, 8N1. DIV = clock / baud, rounded: 27 MHz / 115200 = 234.375 -> 234.module uart_tx #(    parameter DIV = 234) (    input  wire       clk,    input  wire       rst_n,    input  wire [7:0] data,    input  wire       start,      // one-clock pulse; ignored while busy    output reg        tx,         // idles high    output wire       busy);    reg [15:0] tick;              // clocks within the current bit    reg [3:0]  bit_idx;           // 0 = start bit, 1..8 = data, 9 = stop bit    reg [9:0]  frame;    reg        active;    assign busy = active;    always @(posedge clk or negedge rst_n) begin        if (!rst_n) begin            tx <= 1'b1; active <= 1'b0; tick <= 0; bit_idx <= 0; frame <= 10'h3FF;        end else if (!active) begin            tx <= 1'b1;            if (start) begin                frame   <= {1'b1, data, 1'b0};   // stop, data (LSB first), start                active  <= 1'b1;                tick    <= 0;                bit_idx <= 0;                tx      <= 1'b0;                  // start bit begins now            end        end else if (tick == DIV - 1) begin            tick <= 0;            if (bit_idx == 9) begin                active <= 1'b0;                   // stop bit done                tx     <= 1'b1;            end else begin                bit_idx <= bit_idx + 1'b1;                tx      <= frame[bit_idx + 1];            end        end else begin            tick <= tick + 1'b1;        end    endendmodule
P: Listing 26.4 — A testbench with a behavioral receiver that samples each bit in its middle, checks four bytes, and measures the baud rate (Verilog, Icarus).
P: // Testbench: a behavioral receiver samples tx in the middle of each bit and checks the bytes.`timescale 1ns/1psmodule uart_tb;    localparam DIV = 234;    reg clk = 0, rst_n = 0, start = 0;    reg [7:0] data;    wire tx, busy;    integer errors = 0, k;    reg [7:0] got;    reg [7:0] tests [0:3];    real t0, t1;    uart_tx #(.DIV(DIV)) dut (.clk(clk), .rst_n(rst_n), .data(data), .start(start), .tx(tx), .busy(busy));    always #18.518 clk = ~clk;                   // 27 MHz    task receive(output [7:0] b);        integer n;        begin            @(negedge tx);                          // start bit edge            t0 = $realtime;            repeat (DIV / 2) @(posedge clk);        // middle of the start bit            if (tx !== 1'b0) $display("FAIL: start bit not low");            for (n = 0; n < 8; n = n + 1) begin                repeat (DIV) @(posedge clk);                b[n] = tx;                          // LSB first            end            repeat (DIV) @(posedge clk);            if (tx !== 1'b1) begin errors = errors + 1; $display("FAIL: stop bit not high"); end            t1 = $realtime;        end    endtask    initial begin        tests[0] = 8'h55; tests[1] = 8'hA3; tests[2] = 8'h00; tests[3] = 8'hFF;        $dumpfile("uart.vcd");        $dumpvars(0, uart_tb);        #100 rst_n = 1;        for (k = 0; k < 4; k = k + 1) begin            fork                receive(got);                          // listening before the start bit                begin                    @(negedge clk) begin data = tests[k]; start = 1; end   // away from the DUT's edge                    @(negedge clk) start = 0;                end            join            if (got !== tests[k]) begin                errors = errors + 1;                $display("FAIL sent %h got %h", tests[k], got);            end else                $display("ok   sent %h got %h", tests[k], got);            wait (!busy);        end        $display("bit time %.1f ns -> %.0f baud", (t1 - t0) / 9.5, 9.5e9 / (t1 - t0));        $display("%0d errors", errors);        $finish;    endendmodule
H2: Worked Example 26.2: The divider and an off-by-one
P: Problem. Find the divider for 115 200 baud from 27 MHz and the resulting error. Then suppose the comparison in the transmitter is written tick == DIV instead of tick == DIV - 1. What happens, and which test catches it?
P: Solution. 27 000 000/115 200 = 234.375, so DIV = 234, a bit time of 8.667 µs and 115 385 baud, +0.16 %, far inside the few percent a UART tolerates (Chapter 9). The testbench of Listing 26.4 received 55, A3, 00, and FF correctly and measured a bit time of 8666 ns, 115 388 baud, which agrees with 115 385 within its simulated clock period of 37.036 ns. With tick == DIV the counter runs 0 to 234, 235 clocks per bit, so 114 894 baud, −0.27 %. The bytes would still decode, because the error is small, so a test that checks only the bytes passes; the measured baud rate in the testbench shows the error. Off-by-one errors in counters are the most common HDL bug, and the reason the testbench measures time, not only data.

H2: 26.3 From simulation to a board
P: An FPGA is a chip full of lookup tables, flip-flops, memory blocks, and programmable wiring; synthesis turns the HDL into those resources, place and route positions and connects them, and the result is a bitstream loaded at power-up. Inexpensive boards make this a hobby: the Tang Nano 9K (Gowin GW1NR-9, about 8640 lookup tables, 27 MHz oscillator) and the iCEBreaker (Lattice iCE40UP5K, 12 MHz) are typical, both usable with the open-source flow of Yosys for synthesis, nextpnr for place and route, and openFPGALoader or iceprog to load the board, or with the vendor's own tools. A constraints file ties each top-level port to a physical pin and its I/O standard.
P: Listing 26.5 — The Tang Nano 9K top level: a breathing LED from the PWM block and one UART byte per second from the transmitter (Verilog).
P: `timescale 1ns/1ps// Tang Nano 9K top level: a "breathing" LED from the PWM block and one UART byte per second.module top (    input  wire       sys_clk,      // 27 MHz crystal oscillator    input  wire       btn_n,        // user button (pin 4), active low: used as reset    output wire       led_n,        // LED, active low    output wire       uart_tx       // to the on-board USB-UART bridge);    wire rst_n = btn_n;    // Slow ramp for the duty value: changes every 2^17 clocks (4.85 ms), 0..255..0 in 2.5 s.    reg [24:0] slow;    reg        down;    reg [7:0]  duty;    always @(posedge sys_clk or negedge rst_n) begin        if (!rst_n) begin            slow <= 0; duty <= 0; down <= 1'b0;        end else begin            slow <= slow + 1'b1;            if (slow[16:0] == 17'h1FFFF) begin                if (!down && duty == 8'hFF) down <= 1'b1;                else if (down && duty == 8'h00) down <= 1'b0;                else duty <= down ? duty - 1'b1 : duty + 1'b1;            end        end    end    wire pwm_out;    pwm #(.WIDTH(8)) u_pwm (.clk(sys_clk), .rst_n(rst_n), .duty(duty), .out(pwm_out));    assign led_n = ~pwm_out;    // One byte per second: 27 000 000 clocks.    reg [24:0] sec;    reg [7:0]  counter;    reg        start;    wire       busy;    always @(posedge sys_clk or negedge rst_n) begin        if (!rst_n) begin            sec <= 0; counter <= 0; start <= 1'b0;        end else begin            start <= 1'b0;            if (sec == 25'd26_999_999) begin                sec <= 0;                if (!busy) begin start <= 1'b1; counter <= counter + 1'b1; end            end else                sec <= sec + 1'b1;        end    end    uart_tx #(.DIV(234)) u_tx (.clk(sys_clk), .rst_n(rst_n), .data(counter), .start(start),                               .tx(uart_tx), .busy(busy));endmodule

H2: Worked Example 26.3: Timing the breathing LED
P: Problem. In Listing 26.5 the duty value changes once every 2¹⁷ clocks and ramps from 0 to 255 and back. Find the step time and the breathing period, and check that the one-second counter is right.
P: Solution. 2¹⁷/27 MHz = 131 072/27 000 000 = 4.85 ms per step; 2 × 256 steps take 2.49 s for one breath, close to the 2.5 s in the comment. The one-second counter counts 0 to 26 999 999, 27 000 000 clocks, exactly 1.000 s; a 25-bit register holds up to 33 554 431, enough. The usual mistake is to compare with 27 000 000 and get one extra clock per second, harmless here and fatal in a frequency counter.
H2: 26.4 From FPGA to ASIC
P: Firmware and HDL follow different flows after the code is written. Firmware is compiled, flashed in seconds, and fixed by an update. An HDL design is simulated, prototyped on an FPGA, and then, if volume, power, or cost demand it, turned into an ASIC: synthesized to a library of standard cells, placed and routed, checked for timing and manufacturing rules, and sent to a foundry. After tapeout a fix means new masks and months. The open-source tools (Yosys, OpenROAD, OpenLane) and open process design kits such as SkyWater's 130 nm now let individuals do this. Tiny Tapeout pools many small designs on one shared chip: one tile is about 160 × 100 µm, room for roughly a thousand logic gates, with 8 inputs, 8 outputs, and 8 bidirectional pins plus clock and reset; designs are entered in Verilog or drawn in the Wokwi simulator, hardened automatically by a GitHub Actions flow, and manufactured in about six to nine months. In October 2026 its price calculator showed about €70 per tile, with a development board extra. The fab, the process, and the economics of chips are Book 3's.

H2: 26.5 AI-assisted HDL
P: The method of Chapter 25 applies, with higher stakes and some HDL-specific traps. Assistants write Verilog that simulates but does not synthesize (delays and initial blocks in design code), blocking assignments in clocked blocks that change the behavior, incomplete if statements in combinational blocks that create latches, mismatched widths that silently truncate, and counters off by one. Ask for the testbench first, from the spec, with measured timing and not only data checks; then the design; then run both through Verilator's lint and the simulator before any synthesis. A design that has not passed a self-checking testbench is not reviewed yet, whoever wrote it.
P: Key idea. HDL describes circuits that run in parallel on every clock edge. Simulate with a self-checking testbench that measures timing, lint with Verilator, prototype on an inexpensive FPGA, and treat an ASIC tapeout as the point after which nothing can be patched.
P: Common misconception. Writing Verilog as if it were C: a sequence of blocking assignments in a clocked block, expecting each line to happen after the previous one. In hardware every register updates at the same edge; use <= in clocked blocks and = only in combinational ones.
P: AI Pair-Programming Note
P: Ask the assistant to explain, for every always block it writes, whether it describes flip-flops or combinational logic, and what each register holds after reset. An answer that cannot say is a design that is not understood, and the same question is a good review for code you wrote yourself.
P: On the Job
P: On the Job: In chip companies verification engineers often outnumber designers, and their tools (SystemVerilog with UVM, formal property checking, coverage metrics) are a career of their own. The habit that transfers to every level is the one in this chapter: a design is finished when an independent testbench says so, not when the designer believes it.
BENCH: Before loading a new bitstream, route the signal you care about to a spare pin as well, and look at it with the logic analyzer from Chapter 23. The PWM frequency, the UART bit time, and the reset behavior are then measured on the real board in a minute, against the numbers the simulation predicted.
