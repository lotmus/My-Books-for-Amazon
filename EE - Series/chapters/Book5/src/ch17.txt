H1: Chapter 17. Interleaving, Rate Matching, and Error Detection
P: Chapter 7 described codes as mathematical objects. A real modem wraps them in three practical layers: a cyclic redundancy check that tells the receiver whether the decoded block is right, rate matching that adjusts one mother code to whatever rate the link adaptation of Chapter 15 chooses, and interleaving that scatters the burst errors of a fading channel so the decoder sees them as random. This chapter explains each and the arithmetic that sizes it.
H2: 17.1 The CRC
P: A cyclic redundancy check appends to each block the remainder of dividing its bits, as a polynomial, by a fixed generator polynomial. The receiver repeats the division; a nonzero remainder flags an error. An L-bit CRC detects every burst of L bits or fewer and misses a random error pattern with probability about 2^(−L). HARQ, Chapter 15's retransmission scheme, relies on the CRC to decide whether to acknowledge; 5G uses 24-bit CRCs on data blocks and shorter ones on control messages.
EQ: P(undetected) ≈ 2^(−L)
H2: Worked Example 17.1
WEP: A link sends 10⁶ blocks per second, of which 10% fail decoding. With a 24-bit CRC, how often does an erroneous block pass undetected?
WES: 10⁵ failed blocks per second, each passing with probability 2^(−24) = 5.96 × 10⁻⁸, gives 0.006 undetected errors per second, about one every 2.8 minutes. Higher layers add their own checks, which is why such a residual rarely reaches an application.
H2: 17.2 Puncturing and rate matching
P: Rather than design a separate code for every rate, modems use one low-rate mother code and puncture it, deleting some coded bits according to a known pattern, to raise the rate, or repeat bits to lower it. A rate-1/3 mother code turns k information bits into 3k coded bits; to send at rate 3/4 the transmitter keeps 4k/3 of them, 4/9 of the coded bits, and punctures the remaining 5/9. 5G's rate matching writes the LDPC output into a circular buffer and reads the number of bits the allocation requires, starting from different points for each HARQ retransmission, which is how incremental redundancy sends new parity bits each time.
EQ: fraction kept = Rmother / Rtarget
H2: Worked Example 17.2
WEP: A rate-1/3 mother code is punctured to rate 2/3 and then to rate 5/6. What fraction of coded bits is kept in each case?
WES: For 2/3: (1/3)/(2/3) = 1/2, so half the coded bits are sent. For 5/6: (1/3)/(5/6) = 0.4, so 60% are punctured. The more bits are punctured, the less redundancy remains and the higher the SNR the decoder needs, which is the ladder of MCS entries in Chapter 15.
KEY: Key idea. A modem wraps its code in practical layers: a CRC that detects failures, rate matching that punctures or repeats one mother code to any rate, and interleaving that spreads fades across many codewords so the decoder sees scattered errors.
H2: 17.3 Interleaving
P: Codes correct scattered errors well and long bursts poorly, but a deep fade, Chapter 5's Rayleigh dip, destroys a burst of consecutive symbols. An interleaver reorders the coded bits before transmission so that bits adjacent in the codeword are far apart in time or frequency; the receiver undoes the reordering, and the burst becomes scattered errors. To be effective, the interleaver must span several coherence times, which adds latency equal to its span. OFDM gets much of this benefit for free by spreading a codeword across subcarriers separated by more than the coherence bandwidth.
EQ: interleaver span ≳ several × Tc  (time) or several × Bc  (frequency)
H2: Worked Example 17.3
WEP: A slowly moving receiver sees fades lasting about 5 ms at 1 Mbit/s. How many bits does one fade destroy, and what latency does an interleaver spanning ten fade durations add?
WES: 5 ms at 1 Mbit/s is 5000 consecutive bits. An interleaver spanning ten fades covers 50 ms, adding 50 ms of delay, acceptable for streaming but not for a voice call or control loop. Low-latency systems therefore rely on frequency diversity across subcarriers and on HARQ rather than long time interleaving.
H2: 17.4 Scrambling
P: A long run of identical bits, or a repeated pattern, produces spectral lines and starves the receiver's timing and gain loops of transitions. Every standard therefore scrambles the data with a pseudorandom sequence before coding or modulation. The 802.11 scrambler is a 7-bit linear-feedback shift register with the polynomial x⁷ + x⁴ + 1, which repeats every 127 bits and is reset at the start of each packet from a seed carried in the service field. Cellular systems go further: the scrambling sequence in LTE and 5G NR is a length-31 Gold sequence initialized from the cell identity and the user's identity, so that interference from a neighboring cell or another user looks like noise rather than like a valid signal. Scrambling is not encryption. Anyone who knows the standard can undo it; its job is statistical, not secret.
H2: 17.5 The 5G LDPC code in practice
P: The 5G NR data channel uses two quasi-cyclic LDPC base graphs. Base graph 1, with 22 systematic columns, is for large blocks up to 8448 bits and high code rates down to 1/3; base graph 2, with 10 systematic columns, handles blocks up to 3840 bits and rates down to 1/5. Each entry of the base graph is replaced by a Z × Z shifted identity matrix, with 51 lifting sizes Z from 2 to 384, so one decoder structure serves every block size. Transport blocks larger than the maximum are split into code blocks, each with its own 24-bit CRC, so that HARQ can retransmit only the code blocks that failed. Rate matching, Section 17.2, reads the encoded bits from a circular buffer starting at one of four redundancy versions.
H2: Worked Example 17.4
WEP: A base station decodes 100 000 code blocks per second at a block error rate of 10 %. Each block carries a 24-bit CRC. How often does an erroneous block pass the CRC undetected?
WES: 10 000 blocks per second are in error. A good 24-bit CRC misses a random error pattern with probability 2⁻²⁴ = 6.0 × 10⁻⁸, so 10⁴ × 6.0 × 10⁻⁸ = 6.0 × 10⁻⁴ undetected errors per second, one every 28 minutes. That is why higher layers add their own checks, and why the transport block carries a second CRC on top of the code-block CRCs.
H2: Worked Example 17.5
WEP: An 802.11 scrambler uses x⁷ + x⁴ + 1. What is its period, and why is the seed changed for each packet?
WES: A maximal-length 7-bit register cycles through all 2⁷ − 1 = 127 nonzero states, so the sequence repeats every 127 bits. Changing the seed means that a packet whose data happen to correlate with one scrambling phase, producing a bad spectral line, will not do so on its retransmission.
H2: 17.6 ARQ efficiency and parallel HARQ processes
P: A sender that waits for an acknowledgment before sending the next block wastes the round trip. If a block takes T_f to send and the acknowledgment arrives a round trip T_rt after it ends, stop-and-wait uses the channel only a fraction T_f/(T_f + T_rt) of the time. Go-back-N and selective-repeat ARQ keep sending while acknowledgments are in flight, at the cost of buffering and sequence numbers. LTE and 5G keep the simplicity of stop-and-wait but run several processes in parallel, each waiting for its own acknowledgment while the others use the channel: eight processes in LTE FDD, whose HARQ round trip is 8 ms with 1 ms subframes, and up to sixteen, or thirty-two in Release 17 for satellites, in NR.
H2: Worked Example 17.6
WEP: An LTE link sends 1 ms subframes with an 8 ms HARQ round trip measured from the start of one transmission to the earliest retransmission. Find the efficiency of a single stop-and-wait process, and the number of processes needed to keep the channel full.
WES: One process transmits once every 8 ms, using 1/8 = 12.5 % of the subframes. Eight processes, each offset by one subframe, fill every subframe. A satellite link with a 25 ms round trip at 1 ms slots would need 25 or more processes, which is why NTN raised the limit to 32 and allows HARQ to be disabled.
H2: 17.7 Reed-Solomon codes
P: The CRC detects errors; a close relative corrects them. Reed-Solomon codes work on symbols of m bits rather than single bits. An RS(n, k) code adds n − k parity symbols to k data symbols and corrects any t = (n − k)/2 erroneous symbols, however many bits in each symbol are wrong. That makes it ideal against bursts: a burst of 30 bit errors in 10-bit symbols ruins at most four symbols. RS codes protect CDs and DVDs, QR codes, the outer layer of DVB-T and of deep-space links, and the PAM4 Ethernet lanes of Chapter 1, whose RS(544, 514) "KP4" code over 10-bit symbols corrects 15 symbol errors per 5440-bit codeword. Their decoders are algebraic, not iterative, which gives a fixed and short latency that suits a 100 Gbit/s link.
EQ: t = (n − k) / 2  symbols
H2: Worked Example 17.7
WEP: Find the overhead and the correction capability of the RS(544, 514) code used on 100 Gbit/s PAM4 lanes, and the longest single burst of bit errors it is certain to correct.
WES: The overhead is 544/514 − 1 = 5.8 %, which is why the 100 Gbit/s payload becomes 106.25 Gbit/s on the wire once the 64b/66b-derived 256b/257b coding is added. It corrects t = 30/2 = 15 symbols. A burst of b bits touches at most ⌈(b − 1)/10⌉ + 1 symbols, so any burst up to 141 bits, which touches at most 15 symbols, is corrected; longer bursts may be, depending on where they start.
P: Error detection, rate matching, interleaving, and scrambling are the bookkeeping of the physical layer. Chapter 18 returns to the antennas, now in their hundreds.
