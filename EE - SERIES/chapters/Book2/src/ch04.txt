H1: Chapter 4 — Combinational and Sequential Circuits
P: Why does a pocket calculator remember the number you typed while you reach for the next key? Combinational logic can only react to what is in front of it. Memory needs feedback, and this chapter is where circuits start to remember.
P: Where you meet this: Counters and timers in every microcontroller, shift registers driving LED displays, state machines in FPGAs, and the registers inside a processor.
P: Boolean algebra describes what a circuit computes; this chapter is about the two fundamentally different ways a real circuit can be built around it. A combinational circuit's output depends only on its present inputs — it has no memory of what came before. A sequential circuit's output depends on its present inputs and on its history, which requires the circuit to store state somewhere. Nearly everything a digital system does is some combination of the two.
H2: 4.1 Combinational Building Blocks
P: A half adder adds two single bits, A and B, producing a sum bit S = A ⊕ B (the XOR operation from Chapter 3's practice problems) and a carry bit C = AB. A half adder cannot accept a carry from a previous stage, which is what makes it “half” rather than complete. A full adder fixes this by accepting a third input, a carry-in Cᵢₙ, and can therefore be chained: the carry-out of one full adder becomes the carry-in of the next, building an adder for numbers of any width one bit at a time.
WE: Worked Example 4.1
PROB: Build a full adder from two half adders and a single OR gate, and verify it correctly adds A = 1, B = 1, Cᵢₙ = 1.
SOL: The first half adder combines A and B: S₁ = A ⊕ B = 1 ⊕ 1 = 0, and C₁ = AB = 1. The second half adder combines that sum with the carry-in: S = S₁ ⊕ Cᵢₙ = 0 ⊕ 1 = 1, and C₂ = S₁·Cᵢₙ = 0·1 = 0. The final carry-out is C₁ + C₂ = 1 + 0 = 1 (an OR gate combining the two half-adder carries). The result, sum = 1 and carry = 1, is exactly 1 + 1 + 1 = 3, written in binary as 11 — confirming the circuit.

H2: 4.2 Why Sequential Circuits Need Memory
P: A combinational adder is stateless by construction: feed it the same two numbers twice, in any order, and it produces the same sum both times. Many useful behaviors cannot be built this way — a counter that increments on each clock pulse must remember what it counted last, and a system that reacts differently to the same input depending on what happened earlier needs somewhere to keep that history. That somewhere is a bistable element: a circuit with two stable states that, left alone, stays in whichever one it is currently in.
H2: 4.3 Latches and Flip-Flops
P: The simplest bistable element, the SR latch, can be built two ways, and the two are not interchangeable in their details. A NOR-gate version uses active-high inputs: setting S = 1 forces the stored output Q to 1, setting R = 1 forces it to 0, and with both inputs at 0 the latch holds whatever value it last stored — but setting both S and R to 1 simultaneously is forbidden, since both cross-coupled gates are then driven to the same output state, and which stable state the latch settles into once both inputs release is not defined by the circuit. A NAND-gate version instead uses active-low inputs, conventionally written S̄ and R̄: a 0 is what sets or resets the latch, and holding both inputs high is what makes it hold its value. There, the forbidden combination is S̄ = R̄ = 0 — the same underlying problem, with the roles of 0 and 1 inverted.
P: A D flip-flop is the far more common building block in practice: rather than separate set and reset inputs, it has a single data input D and a clock input, and it copies whatever value is on D to its output Q only at the instant the clock transitions (typically low-to-high) — not continuously, the way a latch does. This clocked, edge-triggered behavior is what lets many flip-flops throughout a large digital system change state at exactly the same instant, which is the entire basis of synchronous digital design. A real flip-flop does not sample an arbitrarily changing D at a mathematically precise instant, either: D must actually be stable for a brief setup time before the edge and a brief hold time after it, or the flip-flop's output becomes unpredictable — a timing detail that Chapter 28 treats in full.
FIG: fig4_2.png | Figure 4.2 — A D flip-flop's timing diagram: Q updates to whatever D holds only at each rising CLK edge, then holds steady. | Timing diagram for CLK, D, and Q: Q changes to D at rising clock edges and remains steady between edges.
KEY: A flip-flop's output depends on its history, not only on its current inputs — that dependence on the past is the defining property of memory, and the reason sequential circuits can do things no combinational circuit, however large, ever can.
H2: 4.4 Registers and Counters
P: A register is a bank of D flip-flops sharing one clock, storing one bit of a multi-bit value in each — an 8-bit register is eight D flip-flops wide, storing one full byte at every clock edge. A counter is a register wired so that its own output, modified slightly (typically incremented by one), becomes the input for the next clock edge, causing it to step through a sequence of values automatically rather than storing whatever value is handed to it externally. A shift register is a third variant: each flip-flop's output feeds the next flip-flop's input directly, so a bit pattern loaded in at one end moves one position through the chain on every clock edge, rather than being held in place (a plain register) or incremented (a counter).
WE: Worked Example 4.2
PROB: A 2-bit binary counter, built from two D flip-flops, starts at 00 and increments by one on every clock edge. List the sequence of states for the first five clock edges, and identify when it rolls over.
SOL: Counting in 2-bit binary from 00: 00 → 01 → 10 → 11 → 00 → 01. The first five edges therefore produce 01, 10, 11, 00, 01 — and the counter rolls over back to 00 on the fourth edge, since two bits can represent only four distinct values (0 through 3) before the sequence must repeat.
P: This chapter, and the two before it, cover the digital vocabulary this series needs going forward, but they are not a complete treatment of digital design. Propagation delay (how long a gate takes to respond to an input change), clock skew (different flip-flops receiving the same clock edge at very slightly different times), metastability (what happens when a flip-flop's setup or hold time is violated), fan-out (how many gate inputs one output can safely drive), and the practical differences between logic families (TTL, CMOS, LVDS, and others) all matter enormously in a real digital system — and Chapter 28 returns to propagation delay, skew, setup and hold, and metastability with real numbers, while Section 4.5 meets the 4000 and 7400 families on the bench.
H2: 4.5 Logic You Can Build: the 555, the 4000 Series, and the 7400 Series
P: Everything in Chapters 3 and 4 can be built on a breadboard from chips that have been in catalogs for more than fifty years. The 7400 family began as bipolar TTL; its modern 74HC and 74HCT members are CMOS parts that run from 2 V to 6 V in the same pin-outs. The 4000 family (CD4xxx) is older and slower but runs from 3 V to 15 V and draws almost nothing when idle, which makes it a favorite for battery projects. A 555 timer (Chapter 27) supplies the clock. With those three, a counter, a divider, a debouncer, or an electronic die can be built without a line of code, which is the analog-first rule of Book 1's reader lab applied to logic.
LI: CD4017: a decade counter with ten decoded outputs, one high at a time. Clocked by a 555, it makes the classic LED chaser of Figure 4.3.
LI: CD4060: an oscillator and a 14-stage binary divider in one package. With a 32.768 kHz watch crystal, its last output toggles at 2 Hz; one more flip-flop gives the 1 Hz tick of a clock.
LI: 74HC14: six Schmitt-trigger inverters, the standard cure for slow or bouncing inputs (Section 16.7).
LI: 74HC595: an 8-bit shift register with output latches, the part that lets three wires drive eight LEDs or a display.

Bottom: a CD4060 divides a 32.768 kHz watch crystal by 16,384 to 2 Hz, and one D flip-flop halves that to the 1 Hz tick of a clock. | Block diagrams: a 555 astable clocking a CD4017 decade counter driving ten LEDs; a 32.768 kHz crystal into a CD4060 divider and a D flip-flop giving 1 Hz.
WE: Worked Example 4.3
PROB: A 555 astable uses R₁ = 1 kΩ, R₂ = 68 kΩ, and C = 1 µF to clock a CD4017 LED chaser. Find the clock frequency, the time each LED stays lit, and the time for the light to travel all ten LEDs.
SOL: The 555 runs at f = 1.44/((R₁ + 2R₂)C) = 1.44/(137 kΩ × 1 µF) = 10.5 Hz (Section 27.4 explains the formula). The CD4017 advances one output per clock, so each LED is lit for one period, 1/10.5 = 95 ms, and a full pass of ten LEDs takes 0.95 s. Check: raising C to 2.2 µF gives 4.8 Hz and about 2.1 s per pass, a slower chase from the same circuit.
P: Two no-controller classics grow from these parts. A Nixie-tube clock is a CD4060 time base, a chain of counters, and decoders driving tubes that need roughly 170 V to light; the high voltage, not the logic, is the hard part (Section 27.6). A relay computer goes one step further back and builds the gates themselves from relays: each relay is a switch whose coil is a logic input, two contacts in series make AND, two in parallel make OR, and a relay whose own contact feeds its coil holds itself on as a latch. It runs at a few operations per second and clicks audibly, which is the point: you can hear the logic of this chapter happen.
H2: 4.6 From Gates to Programmable Logic: MCU, FPGA, and ASIC
P: Past a few dozen chips, a breadboard of logic becomes a bird's nest, and the design moves inside one part. There are three choices, and an analogy keeps them straight (Figure 4.4). A microcontroller (MCU) is a Swiss Army knife: a fixed processor with a fixed set of tools (timers, PWM, converters, serial ports) that you direct with code, one instruction at a time. An FPGA (field-programmable gate array) is a box of Lego: thousands of small lookup tables and flip-flops, wired together at power-up by a configuration file, all running in parallel on every clock. An ASIC (application-specific integrated circuit) is a custom-built machine: its gates are fixed into the silicon at the factory, which makes it the fastest, the lowest in power, and the cheapest per unit, after a mask set and a design effort that only large volumes justify.
FIG: fig4_4.png | Figure 4.4 — Three ways to put logic in one part. A microcontroller is a Swiss Army knife you direct with code; an FPGA is a box of Lego you rewire at power-up; an ASIC is a custom-built machine fixed at the factory. | Three boxes comparing a microcontroller, an FPGA, and an ASIC, with an arrow toward more speed, lower power, less flexibility, and higher up-front cost.
P: A lookup table (LUT) is the truth table of Chapter 3 stored in a tiny memory. A 4-input LUT holds 16 bits, one per row, and the four inputs select which bit appears at the output. Load different bits and the same hardware becomes AND, XOR, a multiplexer, or any of the 2¹⁶ = 65,536 functions of four inputs. Put a D flip-flop after each LUT and the registers and counters of Section 4.4 appear in configurable form.
P: Nobody draws an FPGA design gate by gate. It is described in a hardware description language such as Verilog or VHDL, and a synthesis tool maps the description onto LUTs and flip-flops. Book 8's chapter HDL: Software That Becomes Hardware (Chapter 26) covers that language side; this book supplies the gates, flip-flops, and timing (Chapter 28) underneath it. Small boards built around Lattice iCE40 FPGAs are inexpensive and can be programmed with a free, open-source toolchain, which makes them a good first FPGA.
P: The ASIC is no longer out of reach for a student either. Tiny Tapeout, a community project, collects many small designs onto one shared chip made in a commercial foundry from an open-source process design kit, so that a hobbyist or a class can have a small tile of logic built into real silicon for the cost of a hobby project rather than a mask set. The design flow is the FPGA flow with one difference that changes everything: there is no reprogramming after the chips come back.
WE: Worked Example 4.4
PROB: How many configuration bits does a 6-input LUT need, and how many different logic functions can it implement? An FPGA has 5,000 four-input LUTs; how many configuration bits do the LUTs alone hold?
SOL: A k-input LUT stores one bit for each row of its truth table, and there are 2ᵏ rows. For k = 6 that is 2⁶ = 64 bits, and since each of the 64 bits can be 0 or 1 independently, the LUT can implement 2⁶⁴ ≈ 1.8 × 10¹⁹ functions. For the FPGA, each 4-input LUT holds 2⁴ = 16 bits, so 5,000 LUTs hold 80,000 bits, about 10 kB, before the routing switches that wire them together, which in a real device take several times more. Check: a 2-input LUT has 4 bits and 2⁴ = 16 functions, which is the count of every possible two-input truth table: AND, OR, XOR, NAND, NOR, XNOR, and ten others.
KEY: Microcontroller, FPGA, ASIC: code on fixed hardware, hardware rewired in the field, hardware fixed at the factory. Choose the most flexible one that is fast enough, cheap enough, and frugal enough with power.
BENCH: Debounce every mechanical input before it reaches a counter or edge-triggered logic. A switch contact can bounce for a millisecond or more, and a counter will dutifully count every bounce. An RC filter followed by a Schmitt-trigger input, or a few milliseconds of software filtering, fixes it.
P: On the Job
P: Digital hardware jobs split along the line of Figure 4.4. Firmware engineers write code for microcontrollers (Book 8). FPGA engineers describe hardware in Verilog or VHDL and spend much of their week in simulation and timing reports (Chapter 28). ASIC engineers do the same at larger scale, beside verification teams that can outnumber the designers. All of them still reach for a 74HC14 or a 555 on a prototype board when a signal needs cleaning up. Learn the gate here, buy the IC at work, and know which of the three parts the job really needs.
