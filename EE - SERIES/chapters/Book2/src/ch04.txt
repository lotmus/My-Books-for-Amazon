H1: Chapter 4 — Combinational and Sequential Circuits
P: Why does a pocket calculator remember the number you typed while you reach for the next key? Combinational logic can only react to what is in front of it. Memory needs feedback, and this chapter is where circuits start to remember.
P: Where you meet this: Counters and timers in every microcontroller, shift registers driving LED displays, state machines in FPGAs, and the registers inside a processor.
P: Boolean algebra describes what a circuit computes; this chapter is about the two fundamentally different ways a real circuit can be built around it. A combinational circuit's output depends only on its present inputs — it has no memory of what came before. A sequential circuit's output depends on its present inputs and on its history, which requires the circuit to store state somewhere. Nearly everything a digital system does is some combination of the two.
H2: 4.1 Combinational Building Blocks
P: A half adder adds two single bits, A and B, producing a sum bit S = A ⊕ B (the XOR operation from Chapter 3's practice problems) and a carry bit C = AB. A half adder cannot accept a carry from a previous stage, which is what makes it “half” rather than complete. A full adder fixes this by accepting a third input, a carry-in Cᵢₙ, and can therefore be chained: the carry-out of one full adder becomes the carry-in of the next, building an adder for numbers of any width one bit at a time.
WE: Worked Example 4.1
PROB: Build a full adder from two half adders and a single OR gate, and verify it correctly adds A = 1, B = 1, Cᵢₙ = 1.
SOL: The first half adder combines A and B: S₁ = A ⊕ B = 1 ⊕ 1 = 0, and C₁ = AB = 1. The second half adder combines that sum with the carry-in: S = S₁ ⊕ Cᵢₙ = 0 ⊕ 1 = 1, and C₂ = S₁·Cᵢₙ = 0·1 = 0. The final carry-out is C₁ + C₂ = 1 + 0 = 1 (an OR gate combining the two half-adder carries). The result, sum = 1 and carry = 1, is exactly 1 + 1 + 1 = 3, written in binary as 11 — confirming the circuit.

H2: 4.2 Why Sequential Circuits Need Memory
P: A combinational adder is stateless by construction: feed it the same two numbers twice, in any order, and it produces the same sum both times. Many useful behaviors cannot be built this way — a counter that increments on each clock pulse must remember what it counted last, and a system that reacts differently to the same input depending on what happened earlier needs somewhere to keep that history. That somewhere is a bistable element: a circuit with two stable states that, left alone, stays in whichever one it is currently in.
H2: 4.3 Latches and Flip-Flops
P: The simplest bistable element, the SR latch, can be built two ways, and the two are not interchangeable in their details. A NOR-gate version uses active-high inputs: setting S = 1 forces the stored output Q to 1, setting R = 1 forces it to 0, and with both inputs at 0 the latch holds whatever value it last stored — but setting both S and R to 1 simultaneously is forbidden, since both cross-coupled gates are then driven to the same output state, and which stable state the latch settles into once both inputs release is not defined by the circuit. A NAND-gate version instead uses active-low inputs, conventionally written S̄ and R̄: a 0 is what sets or resets the latch, and holding both inputs high is what makes it hold its value. There, the forbidden combination is S̄ = R̄ = 0 — the same underlying problem, with the roles of 0 and 1 inverted.
P: A D flip-flop is the far more common building block in practice: rather than separate set and reset inputs, it has a single data input D and a clock input, and it copies whatever value is on D to its output Q only at the instant the clock transitions (typically low-to-high) — not continuously, the way a latch does. This clocked, edge-triggered behavior is what lets many flip-flops throughout a large digital system change state at exactly the same instant, which is the entire basis of synchronous digital design. A real flip-flop does not sample an arbitrarily changing D at a mathematically precise instant, either: D must actually be stable for a brief setup time before the edge and a brief hold time after it, or the flip-flop's output becomes unpredictable — a timing detail this book will not need until it becomes a first-class design concern in a later book, but worth knowing exists.
FIG: fig4_2.png | Figure 4.2 — A D flip-flop's timing diagram: Q updates to whatever D holds only at each rising CLK edge, then holds steady.
KEY: A flip-flop's output depends on its history, not only on its current inputs — that dependence on the past is the defining property of memory, and the reason sequential circuits can do things no combinational circuit, however large, ever can.
H2: 4.4 Registers and Counters
P: A register is simply a bank of D flip-flops sharing one clock, storing one bit of a multi-bit value in each — an 8-bit register is eight D flip-flops wide, storing one full byte at every clock edge. A counter is a register wired so that its own output, modified slightly (typically incremented by one), becomes the input for the next clock edge, causing it to step through a sequence of values automatically rather than storing whatever value is handed to it externally. A shift register is a third variant: each flip-flop's output feeds the next flip-flop's input directly, so a bit pattern loaded in at one end moves one position through the chain on every clock edge, rather than being held in place (a plain register) or incremented (a counter).
WE: Worked Example 4.2
PROB: A 2-bit binary counter, built from two D flip-flops, starts at 00 and increments by one on every clock edge. List the sequence of states for the first five clock edges, and identify when it rolls over.
SOL: Counting in 2-bit binary from 00: 00 → 01 → 10 → 11 → 00 → 01. The first five edges therefore produce 01, 10, 11, 00, 01 — and the counter rolls over back to 00 on the fourth edge, since two bits can represent only four distinct values (0 through 3) before the sequence must repeat.
P: This chapter, and the two before it, cover the digital vocabulary this series needs going forward, but they are not a complete treatment of digital design. Propagation delay (how long a gate takes to respond to an input change), clock skew (different flip-flops receiving the same clock edge at very slightly different times), metastability (what happens when a flip-flop's setup or hold time is violated), fan-out (how many gate inputs one output can safely drive), and the practical differences between logic families (TTL, CMOS, LVDS, and others) all matter enormously in a real digital system — and all of them are left for a later, dedicated treatment rather than compressed into a paragraph here.
BENCH: Debounce every mechanical input before it reaches a counter or edge-triggered logic. A switch contact can bounce for a millisecond or more, and a counter will dutifully count every bounce. An RC filter followed by a Schmitt-trigger input, or a few milliseconds of software filtering, fixes it.
