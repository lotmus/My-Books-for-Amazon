H1: Chapter 15. Fixed-Point Math and DSP
P: The filter worked perfectly in Python. Ported to the RP2040 as integer code, it settled at 985 instead of 1000 and stayed there forever, fifteen counts short of the truth, with no error, no warning, and a correct-looking formula on the screen. Integer arithmetic throws away everything after the binary point, and a filter that adds a small fraction of the error at each step can round that fraction down to zero. This chapter shows how to keep the fractions you need, and when a chip with a floating-point unit makes the question disappear.
P: Where you meet this: Audio and vibration processing, motor control loops, sensor smoothing, battery fuel gauges, and any filter or FFT on a microcontroller without a floating-point unit.
H2: 15.1 Do you need fixed point?
P: A floating-point unit (FPU) does float arithmetic in hardware in one or a few cycles. Without one, the compiler calls software routines that take tens to hundreds of cycles per operation. The reader-lab chips differ: the RP2040's Cortex-M0+ cores have no FPU; the RP2350's Cortex-M33 cores, the STM32F4 and the nRF52840 have a single-precision FPU; the ESP32-S3 has a single-precision FPU; the Teensy 4.1's Cortex-M7 has a double-precision FPU. On a single-precision FPU, write float and the f suffix (0.5f, sinf), because a stray double constant silently pulls in slow software double arithmetic. Fixed point remains the choice on chips without an FPU, in tight interrupt routines, and wherever the result must be bit-exact on every platform.
H2: 15.2 The Q format
P: A fixed-point number is an integer with an agreed scale. In Q15, a 16-bit signed integer stands for raw/32768, covering −1 to slightly under +1 in steps of about 30.5 millionths. Adding two Q15 numbers is an integer addition. Multiplying gives a Q30 product in 32 bits, which is shifted right by 15 to return to Q15, with rounding if you add half an LSB first. The one product that overflows is −1 × −1 = +1, which Q15 cannot represent, so the result is saturated to the largest value.
H2: Worked Example 15.1: A Q15 multiplication
P: Problem. Multiply 0.5 by 0.25 in Q15, then multiply −1 by −1.
P: Solution. 0.5 is 16384 and 0.25 is 8192. The product is 134 217 728, which in 32 bits is fine; shifting right by 15 gives 4096, and 4096/32768 = 0.125. For −1 × −1: (−32768)² = 1 073 741 824, shifted right by 15 gives 32768, one above the Q15 maximum of 32767, so the code saturates it to 32767 = 0.99997. Listing 15.1 prints both results.
P: Listing 15.1 — Q15 multiplication with rounding and saturation, and a first-order low-pass filter with and without fractional bits in the state (C, runs on the PC).
P: // Fixed-point helpers and a first-order IIR low-pass for chips without an FPU (RP2040).// Pure C, tested on the PC.#include <stdint.h>#include <stdio.h>typedef int16_t q15_t;                      // value = raw / 32768, range [-1, 1)static q15_t q15_mul(q15_t a, q15_t b){    int32_t p = ((int32_t)a * b + (1 << 14)) >> 15;   // round to nearest    if (p > INT16_MAX) p = INT16_MAX;                  // only -1 * -1 overflows    return (q15_t)p;}// y += (x - y) / 16, naive: the state has no fractional bits.static int32_t iir_naive(int32_t *y, int32_t x) { *y += (x - *y) >> 4; return *y; }// Same filter with 8 extra fractional bits kept in the state.static int32_t iir_scaled(int32_t *acc, int32_t x){    *acc += ((x << 8) - *acc) >> 4;    return (*acc + 128) >> 8;                          // rounded output}int main(void){    printf("0.5 * 0.25 = %d/32768\n", q15_mul(16384, 8192));      // 4096 = 0.125    printf("-1 * -1 saturates to %d\n", q15_mul(INT16_MIN, INT16_MIN));    int32_t yn = 0, acc = 0, n16 = 0;    for (int n = 1; n <= 200; n++) {                   // step from 0 to 1000 counts        iir_naive(&yn, 1000);        int32_t ys = iir_scaled(&acc, 1000);        if (n == 16) n16 = ys;    }    printf("after 16 samples: %ld (64.4 %% of 1000 expected)\n", (long)n16);    printf("after 200 samples: naive %ld, scaled %ld\n", (long)yn, (long)((acc + 128) >> 8));    return 0;}
H2: 15.3 A low-pass filter in one line
P: The first-order IIR low-pass, y ← y + α (x − y), is the workhorse of sensor smoothing. With α = 1/16 the multiplication becomes a shift by 4, which is why the filter is so popular on small chips. The analog equivalent, the RC low-pass, is Book 2's; here the question is what the integer version does.
H2: Worked Example 15.2: Time constant, corner frequency, and the dead band
P: Problem. The filter y ← y + (x − y)/16 runs at 100 Hz. Find its time constant and corner frequency, the response after 16 samples to a step from 0 to 1000, and what the naive integer version settles to.
P: Solution. After n samples the response to a step is 1 − (15/16)^n. For n = 16, (15/16)^16 = 0.356, so the output is 64.4 % of the step, 644. The time constant is −1/ln(1 − 1/16) = 15.5 samples = 0.155 s at 100 Hz, and the corner frequency is 1/(2π × 0.155 s) = 1.03 Hz. The naive integer version computes (x − y) >> 4, which is 0 whenever x − y is below 16, so the output stops moving once it is within 15 counts: Listing 15.1 shows it stuck at 985. Keeping 8 extra fractional bits in the state removes the dead band, and the scaled filter reaches 1000.

P: Common misconception. Shifting a negative number right divides it by a power of two. Right-shifting a negative signed integer is implementation-defined in C (arithmetic on GCC for ARM and Xtensa, but not guaranteed), and even where it is arithmetic it rounds toward minus infinity, so −1 >> 4 is −1, not 0. Test filters with falling as well as rising steps.
H2: 15.4 The FFT on a microcontroller
P: An N-point FFT at sample rate fs splits the spectrum into bins fs/N wide and needs N/fs seconds of data per frame. A tone that does not fall exactly on a bin spreads into its neighbors (leakage), and multiplying the frame by a window such as Hann trades a slightly wider peak for far lower leakage. The spectral view of signals is Book 5's. On the chip, use the vendor's optimized library rather than writing your own: CMSIS-DSP on ARM (arm_rfft_fast_f32 on the Teensy 4.1 or an STM32F4) and Espressif's ESP-DSP on the ESP32-S3. Plan the parameters on the PC first, as Listing 15.2 does.
H2: Worked Example 15.3: Planning a vibration FFT
P: Problem. A vibration monitor samples at 10 kHz and runs a 1024-point FFT. Find the bin width, the frame length, and where a 1000 Hz tone lands, and compare leakage with and without a Hann window.
P: Solution. Bin width 10 000/1024 = 9.77 Hz; frame 1024/10 000 = 102.4 ms. The tone sits at bin 1000/9.77 = 102.4, between bins 102 (996.1 Hz) and 103, so it leaks. Listing 15.2 shows the largest component above 1.5 kHz at −42 dB of the peak without a window and −111 dB with Hann. With the window, a small second tone 60 dB down is visible; without it, the leakage would hide it.
P: Listing 15.2 — Planning an FFT on the PC: bin width, frame time, and the effect of a Hann window (Python with NumPy).
P: """Plan an FFT on the PC before writing it for the MCU: bin width, leakage, and the window."""import numpy as npFS = 10_000          # sample rate, HzN = 1024             # FFT lengthF_TONE = 1000.0      # test tone, Hzt = np.arange(N) / FSx = np.sin(2 * np.pi * F_TONE * t)print(f"bin width {FS / N:.2f} Hz, frame {N / FS * 1000:.1f} ms, tone at bin {F_TONE * N / FS:.1f}")for name, w in (("rectangular", np.ones(N)), ("Hann", np.hanning(N))):    spec = np.abs(np.fft.rfft(x * w))    spec_db = 20 * np.log10(spec / spec.max() + 1e-12)    far = spec_db[int(1500 * N / FS):]           # everything above 1.5 kHz    print(f"{name:12s} peak at {np.argmax(spec) * FS / N:7.1f} Hz, leakage above 1.5 kHz {far.max():6.1f} dB")

P: Key idea. Pick the number format from the hardware: float on a chip with an FPU (with the f suffix), fixed point with enough fractional bits where there is none. Test every filter against a floating-point reference on the PC before trusting it on the chip.
P: AI Pair-Programming Note
P: Assistants convert float filters to integer code readily and often reproduce the dead band of Worked Example 15.2, or multiply two 16-bit values into a 16-bit result. Step 4 of the method catches it: ask for a test that compares the integer filter with a float reference over rising and falling steps, and run it on the PC.
BENCH: Feed a known signal before trusting a DSP chain: a function generator at a known frequency and amplitude into the ADC, and check that the peak lands in the expected bin at the expected level. A peak in the wrong bin almost always means the real sample rate differs from the one you assumed.
