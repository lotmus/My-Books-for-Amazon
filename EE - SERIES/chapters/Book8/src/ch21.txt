H1: Chapter 21. Python on the Bench
P: The filter needed a frequency response: sixty points from 100 Hz to 100 kHz, each one a generator setting, a pause, and two readings off the scope. By hand that is an afternoon of turning knobs and typing numbers, with a transposed digit somewhere in the middle. A forty-line Python script does it in thirty seconds, writes a CSV file, plots the result, and does it again identically next week, after the capacitor has been changed. Bench automation is where Python earns its place in every electronics lab.
P: Where you meet this: Characterizing circuits and sensors, production calibration, long-term logging, environmental tests, and every measurement that has to be repeated more than twice.
H2: 21.1 Talking to instruments
P: Almost every bench instrument made in the last twenty years speaks SCPI, a text command language: *IDN? asks for the identity, and commands such as FREQ 1000 or :MEAS:VPP? CHAN1 set and read values. The transport is USB (as a USBTMC device), Ethernet (LXI, VXI-11, or a raw socket), or an old GPIB adapter. PyVISA hides the transport: rm.list_resources() lists the instruments it can see, open_resource opens one by its address string, write sends a command, and query sends one and returns the answer. A VISA library underneath does the work: the vendor's (NI-VISA, Keysight IO Libraries) or the pure-Python pyvisa-py. The command spellings differ between vendors and models, so the programming manual of the instrument is the reference, and a script that controls two brands keeps their commands in separate small classes.

P: Listing 21.1 — A frequency sweep with a function generator and an oscilloscope over SCPI, with a simulation mode for testing without instruments (Python with PyVISA and NumPy).
P: """Frequency sweep of a filter with a function generator and an oscilloscope over SCPI (PyVISA).SCPI command spellings differ between vendors; the ones below follow common forms.Run with --sim to test the script logic without instruments (an ideal RC low-pass)."""import argparseimport csvimport mathimport timeimport numpy as npR, C = 10e3, 10e-9                      # device under test: fc = 1/(2 pi R C) = 1591.5 Hzclass SimBench:    """Stands in for the generator and scope; answers like an RC low-pass with 1 V in."""    def __init__(self):        self.f = 1000.0    def write(self, cmd):        if cmd.startswith("FREQ"):            self.f = float(cmd.split()[1])    def query(self, cmd):        if cmd == "*IDN?":            return "SIM,Bench,0,1.0"        h = 1 / math.sqrt(1 + (2 * math.pi * self.f * R * C) ** 2)        vin = 2.0                                     # 2 Vpp        return str(vin if "CHAN1" in cmd else vin * h)def open_bench(sim):    if sim:        b = SimBench()        return b, b    import pyvisa    rm = pyvisa.ResourceManager()    gen = rm.open_resource("USB0::0x1AB1::0x0642::DG1ZA000000001::INSTR")   # from rm.list_resources()    scope = rm.open_resource("TCPIP0::192.168.1.50::INSTR")    for inst in (gen, scope):        inst.timeout = 5000                              # ms    gen.write("FUNC SIN"); gen.write("VOLT 2.0"); gen.write("OUTP ON")    return gen, scopedef sweep(gen, scope, f_start=100, f_stop=100e3, per_decade=20, settle=0.3):    n = int(round(math.log10(f_stop / f_start) * per_decade)) + 1    rows = []    for f in np.logspace(math.log10(f_start), math.log10(f_stop), n):        gen.write(f"FREQ {f:.3f}")        time.sleep(settle)                                # let the scope's measurement update        vin = float(scope.query(":MEAS:VPP? CHAN1"))        vout = float(scope.query(":MEAS:VPP? CHAN2"))        rows.append((f, vin, vout, 20 * math.log10(vout / vin)))    return rowsdef corner(rows):    """-3 dB frequency by linear interpolation in log(f)."""    for (f1, *_, g1), (f2, *_, g2) in zip(rows, rows[1:]):        if g1 >= -3.0103 > g2:            x = (-3.0103 - g1) / (g2 - g1)            return 10 ** (math.log10(f1) + x * (math.log10(f2) - math.log10(f1)))    return Noneif __name__ == "__main__":    ap = argparse.ArgumentParser()    ap.add_argument("--sim", action="store_true")    args = ap.parse_args()    gen, scope = open_bench(args.sim)    print("instrument:", scope.query("*IDN?").strip())    rows = sweep(gen, scope, settle=0 if args.sim else 0.3)    with open("sweep.csv", "w", newline="") as f:        w = csv.writer(f)        w.writerow(["f_Hz", "vin_Vpp", "vout_Vpp", "gain_dB"])        w.writerows(rows)    print(f"{len(rows)} points, corner at {corner(rows):.1f} Hz (theory {1 / (2 * math.pi * R * C):.1f} Hz)")
H2: Worked Example 21.1: Planning and checking a sweep
P: Problem. The filter is R = 10 kΩ, C = 10 nF. Plan a sweep from 100 Hz to 100 kHz with 20 points per decade and 0.3 s of settling per point, and check the script against theory before connecting instruments.
P: Solution. Three decades at 20 points per decade gives 3 × 20 + 1 = 61 points, logarithmically spaced so each decade gets the same resolution. Time: 61 × 0.3 s = 18 s of settling plus the queries, about half a minute. Theory: fc = 1/(2π × 10 kΩ × 10 nF) = 1591.5 Hz (Book 2's formula). In simulation mode the script prints 61 points and a corner at 1591.2 Hz, so the sweep, the CSV, and the interpolation work; any difference on the real bench is now the circuit or the measurement, not the script. That separation is step 5 of the method applied to bench code.

H2: 21.2 Calibration
P: A sensor that is consistent but offset can be corrected in software. Measure it against a better reference at several points across the range, fit the reference as a function of the sensor reading, and apply that fit in the firmware or the logger. A straight line (gain and offset) is enough for most sensors over a moderate range; the residuals after the fit tell you whether it is. The correction is only as good as the reference and only valid in the conditions of the calibration.

H2: Worked Example 21.2: Calibrating a temperature sensor
P: Problem. A BME280 on the garden node and a reference thermometer are read at seven temperatures from 5 to 35 °C. Find the raw error, the fit, the error after correction, and the corrected value of a reading of 22.00 °C.
P: Solution. The BME280 reads 0.47 °C high on average (maximum 0.59 °C), a typical self-heating offset of a sensor on a board with a warm processor next to it. Listing 21.3 fits ref = 1.00871 × dut − 0.6443, and the residuals drop to 0.024 °C rms and 0.039 °C maximum. A reading of 22.00 °C is corrected to 1.00871 × 22.00 − 0.6443 = 21.55 °C. The residuals now reflect the reference's resolution and the noise, so a curved fit would add nothing; and the result holds only for this board, in this housing, at this measurement rate, because self-heating changes with all three.

H2: 21.3 Logging that survives the night
P: A logging script on the bench runs for hours or days, so it must expect what the bench delivers: a serial port that disappears when the board resets, a malformed line, a full disk, and a PC that goes to sleep. Write each record with a timestamp in UTC (local time jumps twice a year), flush or close the file after every write so a crash loses one line instead of an hour, start a new file every day, and reconnect when the port returns. Chapter 4's logger has the basic pattern; Chapter 17's MQTT subscriber is the networked version.
P: Key idea. Automate any measurement you will repeat: PyVISA and SCPI for the instruments, a simulation mode to test the script without them, CSV files with UTC timestamps, and a plot generated from the file, never from memory.
P: AI Pair-Programming Note
P: Assistants write PyVISA scripts fluently but guess the SCPI commands, mixing one vendor's syntax with another's. Give the instrument model and paste the relevant page of its programming manual into the prompt, and test every command interactively with query before the script runs a sweep.
BENCH: Before automating, type the commands by hand in an interactive Python session: open the instrument, send *IDN?, then each command of the planned script, one at a time, watching the instrument's front panel. Ten minutes of this finds the wrong command spellings, timeouts, and unit surprises that would otherwise appear as a silent wrong curve.
