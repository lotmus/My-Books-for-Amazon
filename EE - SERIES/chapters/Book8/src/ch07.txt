H1: Chapter 7. Timers and PWM: LEDs, Servos, and the Ultrasonic Ranger
P: A hobby servo understands one sentence: a pulse between 1 and 2 milliseconds long, repeated fifty times a second. Make the pulse 1.5 ms and the arm points straight up; make it 1.6 ms and it turns about 18 degrees. Generating that pulse in a software loop works until the processor gets busy, and then the arm twitches. A hardware timer generates it with no help from the CPU at all, accurate to a microsecond, forever. Timers are the most underrated peripheral on the chip.
P: Where you meet this: LED dimming, servos and motor drivers, buzzers, the ultrasonic ranger's echo, frequency counters, periodic sampling, and every "every 10 ms" in a spec.
H2: 7.1 What a timer is
P: A timer is a counter driven by a clock. A prescaler divides the input clock to set the tick rate; the counter counts ticks up to an auto-reload value and starts again, so the overflow rate is the timer frequency. A compare register is compared with the counter on every tick: while the counter is below it the output pin is high, and above it the pin is low. That is PWM, pulse-width modulation, entirely in hardware. Run the same counter the other way, let an input edge copy the counter into a capture register, and the timer measures time instead of making it.
EQ: f_PWM = f_clk / ((PSC + 1)(ARR + 1)),    duty = CCR / (ARR + 1)

P: The PWM electronics, why an LED dims smoothly at a few kilohertz, what the motor driver does with the pulses, and the flyback diode that protects it, are Book 2's. Firmware chooses three numbers: the frequency, the resolution (how many duty steps there are), and the duty itself. The first two trade against each other, because a faster PWM leaves fewer clock ticks per period.
H2: Worked Example 7.1: A 50 Hz servo timer on an STM32
P: Problem. An STM32 timer runs from an 84 MHz clock. Find PSC and ARR for 50 Hz with 1 µs ticks, and the compare values for 1.0, 1.5, and 2.0 ms pulses. Compare with the setting that gives the most duty steps, and with a 20 kHz motor PWM.
P: Solution. For 1 µs ticks the prescaler divides by 84, so PSC = 83. A 20 ms period is 20 000 ticks, so ARR = 19 999. The pulses are CCR = 1000, 1500, and 2000. Listing 7.1 searches for the smallest prescaler that keeps ARR within 16 bits: PSC = 25 and ARR = 64 614, which gives 64 615 steps instead of 20 000 but makes every pulse width an awkward number of ticks. For a servo, 1 µs steps are already finer than the servo can resolve, so the round numbers win. At 20 kHz for a motor driver, PSC = 0 and ARR = 4199: 4200 steps, about 12 bits of resolution, the price of a frequency above human hearing.
P: Listing 7.1 — Solving PSC and ARR for a target PWM frequency (C, runs on the PC).
P: // Prescaler and auto-reload for an STM32 timer: f_pwm = f_clk / ((PSC+1)(ARR+1)).// Runs on the PC; paste the results into CubeMX or the init code.#include <stdint.h>#include <stdio.h>typedef struct { uint32_t psc, arr; double f_actual; } timer_cfg_t;// Choose the smallest prescaler that lets ARR fit in 16 bits (best duty resolution).static int timer_solve(uint32_t f_clk, double f_pwm, timer_cfg_t *out){    for (uint32_t psc = 0; psc <= 0xFFFFu; psc++) {        double arr = f_clk / ((psc + 1.0) * f_pwm) - 1.0;        if (arr <= 65535.0) {            out->psc = psc;            out->arr = (uint32_t)(arr + 0.5);            out->f_actual = f_clk / ((psc + 1.0) * (out->arr + 1.0));            return 0;        }    }    return -1;   // frequency too low for this timer clock}int main(void){    const double targets[] = { 50.0, 1000.0, 20000.0 };    for (int i = 0; i < 3; i++) {        timer_cfg_t c;        if (timer_solve(84000000u, targets[i], &c) == 0)            printf("%8.0f Hz: PSC=%5u ARR=%5u -> %.3f Hz, %u steps\n",                   targets[i], (unsigned)c.psc, (unsigned)c.arr, c.f_actual, (unsigned)c.arr + 1u);    }    return 0;}
H2: 7.2 PWM on the ESP32-S3
P: The ESP32 family has a dedicated LED-control peripheral, LEDC, which despite its name drives anything that needs PWM. You configure a timer with a frequency and a duty resolution in bits, attach channels to pins, and set each channel's duty. The driver computes the clock divider for you. At 50 Hz with 14-bit resolution, one duty step is 20 ms/16 384 = 1.22 µs. The MCPWM peripheral, also on the S3, adds dead time and fault inputs for motor bridges.
P: Listing 7.2 — A servo on the ESP32-S3's LEDC peripheral, with clamping and rounding in angle_to_duty (ESP-IDF, C).
P: // Servo on GPIO 15 of an ESP32-S3 with the LEDC PWM peripheral (ESP-IDF 5.x).// 50 Hz, 14-bit duty: one step = 20 ms / 16384 = 1.22 us.#include <stdint.h>#include "freertos/FreeRTOS.h"#include "freertos/task.h"#include "driver/ledc.h"#define SERVO_GPIO   15#define PERIOD_US    20000u#define DUTY_BITS    LEDC_TIMER_14_BIT#define DUTY_MAX     (1u << 14)#define PULSE_MIN_US 1000u      // 0 degrees (check your servo's data sheet)#define PULSE_MAX_US 2000u      // 180 degreesstatic uint32_t angle_to_duty(float deg){    if (deg < 0.0f)   deg = 0.0f;           // clamp: never drive past the end stops    if (deg > 180.0f) deg = 180.0f;    float us = PULSE_MIN_US + (PULSE_MAX_US - PULSE_MIN_US) * deg / 180.0f;    return (uint32_t)(us * DUTY_MAX / PERIOD_US + 0.5f);   // round to nearest step}void app_main(void){    const ledc_timer_config_t tcfg = {        .speed_mode = LEDC_LOW_SPEED_MODE, .duty_resolution = DUTY_BITS,        .timer_num = LEDC_TIMER_0, .freq_hz = 50, .clk_cfg = LEDC_AUTO_CLK,    };    ESP_ERROR_CHECK(ledc_timer_config(&tcfg));    const ledc_channel_config_t ccfg = {        .gpio_num = SERVO_GPIO, .speed_mode = LEDC_LOW_SPEED_MODE,        .channel = LEDC_CHANNEL_0, .intr_type = LEDC_INTR_DISABLE,        .timer_sel = LEDC_TIMER_0, .duty = angle_to_duty(90.0f), .hpoint = 0,    };    ESP_ERROR_CHECK(ledc_channel_config(&ccfg));    for (;;) {        for (int deg = 0; deg <= 180; deg += 45) {            ESP_ERROR_CHECK(ledc_set_duty(LEDC_LOW_SPEED_MODE, LEDC_CHANNEL_0, angle_to_duty((float)deg)));            ESP_ERROR_CHECK(ledc_update_duty(LEDC_LOW_SPEED_MODE, LEDC_CHANNEL_0));            vTaskDelay(pdMS_TO_TICKS(1000));        }    }}
H2: Worked Example 7.2: How fine can the servo move?
P: Problem. With the LEDC setup of Listing 7.2 (50 Hz, 14 bits) and a servo that maps 1000 to 2000 µs onto 0 to 180°, find the duty values for 0°, 90°, and 180°, and the angle per duty step.
P: Solution. Duty = pulse/20 000 µs × 16 384. For 1000 µs: 819.2, rounded to 819. For 1500 µs: 1228.8, rounded to 1229. For 2000 µs: 1638.4, rounded to 1638. One step is 1.22 µs, and the servo moves 180° per 1000 µs, which is 0.18° per µs, so one step is 0.22°. That is finer than the dead band of a typical hobby servo, so the resolution is not the limit. The usual mistake is to compute with the period in milliseconds and the pulse in microseconds and get a duty a thousand times off; the clamp in angle_to_duty stops an out-of-range angle from driving the servo into its end stop.

H2: 7.3 Measuring time: the ultrasonic ranger
P: The reader lab's ultrasonic sensor turns distance into time. A 10 µs pulse on its trigger pin makes it send a burst of eight 40 kHz cycles; its echo pin then goes high until the reflection returns. The echo width is the round-trip time, so the distance is the speed of sound times the width, divided by two. A timer's input capture measures the width to a tick; MicroPython's time_pulse_us measures it in software, accurately enough for centimeters.
EQ: d = c t / 2,    c ≈ 331.3 + 0.606 T  (m/s, T in °C)
P: Listing 7.3 — Ultrasonic distance with a timeout and temperature compensation (MicroPython).
P: # MicroPython: ultrasonic distance with temperature compensation.# Use a 3.3 V sensor, or divide a 5 V module's echo down to 3.3 V (Book 1).from machine import Pin, time_pulse_usimport timeTRIG = Pin(6, Pin.OUT, value=0)ECHO = Pin(7, Pin.IN)def distance_m(temp_c=20.0):    TRIG.value(1)    time.sleep_us(10)                          # 10 us trigger pulse    TRIG.value(0)    t_us = time_pulse_us(ECHO, 1, 30_000)      # 30 ms timeout, about 5 m    if t_us < 0:        return None                            # no echo: out of range or wiring    c = 331.3 + 0.606 * temp_c                 # speed of sound in m/s    return c * t_us * 1e-6 / 2                 # out and backwhile True:    d = distance_m(temp_c=21.5)                # later: the BME280 temperature    print("no echo" if d is None else "%.3f m" % d)    time.sleep_ms(100)
H2: Worked Example 7.3: Why the ranger needs the BME280
P: Problem. An object is 1.000 m away. Find the echo width at 20 °C. A program that assumes c = 343 m/s is used on a 0 °C morning. What distance does it report?
P: Solution. At 20 °C, c = 331.3 + 0.606 × 20 = 343.4 m/s, and t = 2 × 1.000/343.4 = 5.824 ms. At 0 °C, c = 331.3 m/s and the echo lasts 2/331.3 = 6.037 ms. The program computes 343 × 6.037 ms/2 = 1.035 m, a 3.5 % error, 35 mm at one meter. Passing the BME280's temperature into distance_m removes it. A 1 µs timing resolution corresponds to 0.17 mm of distance, so temperature, not timing, sets the accuracy. The 30 ms timeout in Listing 7.3 caps the range at about 5 m and keeps the loop from hanging when no echo returns.
FIG: fig7_3.png | Figure 7.3 — Ultrasonic ranging timing for an object at 1.000 m and 20 °C (Worked Example 7.3). A 10 µs trigger starts a 200 µs burst of eight 40 kHz cycles; the echo line stays high for 5.824 ms, the round trip. | Three traces on a millisecond axis. Trigger: a 10 microsecond pulse at time zero. Burst: eight 40 kilohertz cycles lasting 0.2 milliseconds. Echo: high from about 0.2 to 6.0 milliseconds, annotated 5.824 milliseconds equals 1.000 meter at 20 degrees.
P: Key idea. Let the hardware keep time. A timer generating PWM or capturing an edge is exact no matter how busy the CPU is; software timing is exact only until the next interrupt.
P: AI Pair-Programming Note
P: Assistants often produce servo code with the pulse range of one servo applied to another, PWM frequencies that are fine for LEDs but wrong for servos, or the legacy ESP-IDF 4 LEDC API mixed with version 5. Check every number against the servo's data sheet and the duty arithmetic against a scope.
BENCH: Never test a new servo routine with the horn attached to a mechanism. Run it free first, watch the pulse on a scope, and confirm the extremes. A servo driven against its end stop draws its stall current continuously, gets hot, and can brown out the ESP32-S3 if both share a weak supply (Book 6 sizes that supply).
