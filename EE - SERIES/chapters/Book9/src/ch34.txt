H1: Chapter 34. SCPI, VISA, IVI, and Programming Instruments in Python and C#
P: For six months the test station reported every regulator's ripple as 2 mV, well inside the limit. Then a returned unit measured 40 mV on the bench. The script had sent VOLT:AC:RANG:AUTOO ON, one letter too many. The DMM beeped once at the start of every shift, put "−113, Undefined header" in its error queue, and kept its previous range, where the ripple was below the resolution. Nobody had read the error queue. A program that talks to instruments must also listen.
MEET: Characterization labs, production test, automated burn-in and environmental test, research setups, calibration labs, and every bench where a measurement is repeated more than a few times.
H2: 34.1 The layers
P: An instrument program has four layers between your code and the measurement. VISA (Virtual Instrument Software Architecture) is the vendor-neutral I/O library: open a resource by name, write, read, close; it hides the transport (GPIB, USB Test and Measurement Class, VXI-11 or HiSLIP over LAN, or a raw socket, usually port 5025). Chapter 11 compares the buses and Section 35.4 decodes the resource names. Above VISA sit, optionally, instrument drivers: IVI drivers (IVI-C, IVI-COM, IVI.NET, from the IVI Foundation) with class-compliant interfaces that let one program run a DMM from either of two vendors, or Python libraries such as PyMeasure and QCoDeS. Inside the instrument, a parser executes the commands, queues the replies, and keeps a status system and an error queue.

H2: 34.2 SCPI and IEEE 488.2
P: SCPI (Standard Commands for Programmable Instruments) is a tree of keywords separated by colons, with short forms in capitals (MEASure:VOLTage:DC? may be sent as MEAS:VOLT:DC?), parameters after a space, queries ending in ?, and commands separated by semicolons. The IEEE 488.2 common commands start with *: *IDN? (identify), *RST (reset to a known state), *CLS (clear status and error queue), *OPC? (reply 1 when all pending operations have finished), *WAI (do not execute the next command until then), *ESR? and *STB? (event status and status byte), *ESE and *SRE (enable masks for the service request), *TST? (self-test). The status byte's bits say whether a message is available (MAV), an error is queued, or an enabled event has occurred; a service request (SRQ) lets the instrument interrupt the controller instead of being polled.
P: Three rules make programs reliable. Start from a known state (*RST and *CLS, then set everything the measurement depends on, never relying on defaults). Synchronize: a query that returns data waits for it, but a configuration command returns immediately, so put *OPC? after configuration blocks and before triggering, and for long operations (calibration, a long sweep) use *OPC with the ESR operation-complete bit and SRQ or status polling rather than a query that times out. Check the error queue (SYST:ERR? until it returns 0) after each configuration block, and fail loudly.
H2: 34.3 Getting data out fast
P: Two things decide throughput: how many round trips the program makes and how many bytes it moves. Each query costs a round trip, typically 0.2 to 2 ms on LAN or USB and more on GPIB; reading 1000 points one at a time costs 1000 round trips. Instruments have trigger systems and buffers so you can configure once, trigger many readings, and fetch them in one transfer. Binary formats beat ASCII: a scope sample as a 16-bit integer is 2 bytes, as text "−1.23456E−03," about 13, and parsing text costs time too. Binary data arrives as an IEEE 488.2 definite-length block, #<n><length><bytes>: #800004000 announces 4000 bytes in an 8-digit length field. Set the byte order (FORM:BORD) to match the parser.
WE: Worked Example 34.1: One query per point or one block
PROB: A DMM takes 1000 readings at NPLC 1 on a 60 Hz line; each query round trip costs 2 ms; the transfer runs at 10 MB/s. Compare one READ? per point with a buffered acquisition fetched as one binary block, at NPLC 1 and at NPLC 0.02.
SOL: NPLC 1 integrates 16.7 ms. Per point: 1000 × (16.7 + 2) ms = 18.7 s. Buffered: 1000 × 16.7 ms + 2 ms + 4000 bytes/10 MB/s = 16.7 s: only 11 % faster, because integration dominates. NPLC 0.02 integrates 0.33 ms: per point 1000 × 2.33 ms = 2.33 s; buffered 0.33 s + 2 ms + 0.4 ms = 0.34 s, seven times faster. Optimize the round trips when the measurement itself is fast; when it is slow, the round trips do not matter.

WE: Worked Example 34.2: The size of a waveform
PROB: A scope record has 1 million points. How many bytes does it take as 8-bit, 16-bit, and ASCII data (13 characters per point), and how long does each take over a link that moves 10 MB/s?
SOL: 8-bit: 1 MB, 0.1 s; 16-bit: 2 MB, 0.2 s; ASCII: 13 MB, 1.3 s, plus the time to parse 1 million numbers. The 16-bit format carries the full resolution of a 10- or 12-bit scope; the binary block header for 2 MB is #72000000, a 7-digit length.

H2: 34.6 Drivers, simulation, and versions
P: Raw SCPI is portable and transparent; drivers add range checking, help, and interchangeability at the cost of another layer to install and version. Many labs use raw SCPI in thin, tested wrappers like Listing 34.1, one per instrument model. Whatever you choose: record *IDN? (including firmware) with every data file, pin library versions, keep a simulation mode so the logic can be tested without hardware, and log every command and reply during development; most instrument bugs are found by reading that log.
MIS: If the program ran without an exception, the instrument did what it was told. Instruments accept wrong commands silently and report them only in the error queue; check SYST:ERR? after each configuration block.
BENCH: Keep an interactive session open beside the script while developing (the vendor's I/O tool, or Python's interactive prompt with PyVISA). Type each command by hand first and read the error queue; then put it in the program.
H2: Practice
PP: 1. (Core) Write the short form of SENSe:VOLTage:DC:NPLCycles 10.
PP: 2. (Core) What does *OPC? return, and when?
PP: 3. (Core) Decode the block header #6100000.
PP: 4. (Extension) A scope transfers 10 million 16-bit points over a link at 40 MB/s. Time? And as ASCII at 13 characters per point?
PP: 5. (Extension) 500 readings at NPLC 0.1 (60 Hz) with 1.5 ms per query: one query per point against a buffered fetch (ignore the transfer)?
PP: 6. (Challenge) A spectrum-analyzer sweep sometimes times out after the analyzer's calibration routine runs. Explain the cause and design the synchronization.
ANS: 1. SENS:VOLT:DC:NPLC 10. The usual mistake is to abbreviate keywords freely (SEN:VOL); only the capitalized short forms are valid.
ANS: 2. The character 1, after all pending operations started before it have finished; until then the query blocks (and can time out). The usual mistake is to use *OPC (no question mark), which sets a status bit and returns nothing.
ANS: 3. One digit 6 gives a 6-digit length field: 100000 bytes follow. The usual mistake is to read 6100000 as the length.
ANS: 4. Binary: 20 MB/40 MB/s = 0.5 s; ASCII: 130 MB/40 MB/s = 3.25 s plus parsing. The usual mistake is to use the sample count instead of bytes.
ANS: 5. NPLC 0.1 = 1.67 ms. Per point: 500 × (1.67 + 1.5) = 1.58 s. Buffered: 500 × 1.67 ms + 1.5 ms = 0.835 s, about twice as fast. The usual mistake is to forget the integration time when comparing.
ANS: 6. The calibration (an alignment of the analyzer) takes longer than the VISA timeout, and a query sent meanwhile waits in the queue until the timeout expires. Fix: either disable automatic alignment during the test and run it at a defined time, or start long operations with *OPC, enable the operation-complete bit in *ESE and the event bit in *SRE, and wait for SRQ (or poll *STB? with short timeouts) before sending the next query; raise the timeout only for the one operation known to be long. The usual mistake is to raise the global timeout to minutes, which hides real hangs.
