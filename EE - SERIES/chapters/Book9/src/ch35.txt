H1: Chapter 35. LabVIEW and TestStand: Graphical Test for the Characterization Lab
P: The new engineer's first job in the characterization lab sounds easy: rerun the threshold-voltage sweep on forty MOSFET samples at 25, 75, and 125 °C. The station's program was written six years ago by someone who has since moved to another site. When it opens, there is no text in it. There is a picture: small boxes, orange and purple wires, gray frames around parts of the drawing, and a window full of knobs and graphs. The program runs three shifts a day, and the whole lab trusts its numbers. It is a LabVIEW VI, and in many semiconductor labs and production test cells this is how the instruments get told what to do. This chapter teaches you to read it, change it safely, and decide when to use it and when to use Python or C# instead.
MEET: Semiconductor characterization labs (I-V and C-V curves over temperature, threshold voltage, on-resistance, leakage), device and module validation, production test stations sequenced by TestStand, university and research labs with NI data acquisition hardware, and any company whose test department has a LabVIEW code base older than its newest engineer.
H2: 35.1 Why the lab bench runs LabVIEW
P: LabVIEW is NI's graphical programming environment for measurement and control; NI has been part of Emerson since October 2023. A LabVIEW program is called a VI, a virtual instrument, because the first ones replaced the front panel of a bench instrument with a window on a PC. Three things keep it in labs. First, hardware: NI's data acquisition, PXI, and modular instrument hardware ships with LabVIEW functions, and most bench-instrument vendors publish LabVIEW drivers, so an SMU, a temperature chamber, and a switch matrix can all be in one program within a day. Second, the user interface comes free: every VI has a window with controls and graphs, so a technician can run a sweep without a separate GUI project. Third, the dataflow model fits measurements: data moves along wires from instrument to analysis to file, and independent parts run in parallel without threads in the code.
P: It also has costs, and they are covered honestly in Sections 35.11 and 35.12: licenses are paid, graphical code does not diff or review like text, and large LabVIEW applications need the same discipline as any other software. TestStand, NI's test sequencer, sits on top: it runs code written in LabVIEW, Python, C#, or C as steps of a production test, with limits, operator prompts, reports, and database logging. This chapter treats both as tools at the bench, next to the SCPI, VISA, Python, and C# of Chapter 34 (Book 8, Chapters 21 and 22, teaches Python and C# as languages). The device physics behind the measurements, threshold voltage and carrier mobility, is in Book 3; fixtures, guarding, and production test economics are in Book 7.
H2: 35.2 Dataflow: VIs, front panels, and wires
P: Every VI has two windows. The front panel is the user interface: controls are inputs (a number to type, a knob, a VISA resource name), indicators are outputs (a number, a graph, an LED). The block diagram is the code: each control and indicator appears there as a terminal, and functions, subVIs, and structures sit between them, connected by wires. A subVI is another VI used as a function, with an icon and a connector pane that defines its inputs and outputs, so a block diagram calls a subVI the way C calls a function.
P: The rule that makes LabVIEW different is dataflow. A node runs when all of its inputs have arrived, and its outputs become available when it finishes. The position of a node on the page means nothing; only the wires decide the order. Two pieces of code with no wire between them have no defined order, and LabVIEW may run them at the same time on different cores. Wires have types, shown by color and thickness: orange for floating-point numbers, blue for integers, pink for strings, green for Booleans, purple for VISA sessions, and a thicker yellow-brown for the error cluster. Thick wires are arrays.
P: The error cluster is how real VIs order their steps. Nearly every instrument function has an error in and an error out terminal. Wiring error out of one call to error in of the next makes the second wait for the first, and a VI that receives an error skips its work and passes the error on. The result is the same as checking a return code after each call in C, but drawn as one wire that runs through the whole diagram.

WE: Worked Example 35.1: What parallel wires save in a sweep
PROB: Each point of the MOSFET sweep sets the gate voltage, waits 5 ms, then reads the drain current and the gate current from two SMUs. Each reading integrates for 1 power-line cycle at 60 Hz and the GPIB transfer adds about 2 ms. One temperature has 465 points. How long does one temperature take when the two readings are made one after the other, and when they are made in parallel on two VISA sessions?
SOL: One power-line cycle at 60 Hz is 1/60 s = 16.7 ms, so one reading takes 16.67 + 2.0 = 18.67 ms. One after the other: 5 + 2 × 18.67 = 42.3 ms per point, and 465 × 42.33 ms = 19.7 s. In parallel: 5 + 18.67 = 23.7 ms per point, and 465 × 23.67 ms = 11.0 s. In LabVIEW the parallel version is the natural drawing: two Query calls on two wires. In Python (Listing 35.2) the calls run in sequence unless you add threads. The saving is real, but Worked Example 35.3 shows that it is small next to the time the device needs to reach temperature.
H2: 35.3 Loops, cases, shift registers, and two patterns
P: Structures are the gray frames on the diagram. A For Loop runs its contents N times, with the count wired to the N terminal and the iteration number available at the i terminal. A While Loop runs until its stop terminal receives true; it always runs at least once. A Case Structure holds several diagrams, one per value of its selector, like a switch statement in C; the selector can be a Boolean, an integer, a string, or an enum. Wires that leave a loop pass through tunnels, and an auto-indexing tunnel collects one value per iteration into an array, which is how the sweep VI builds its Vgs and Id arrays without a single explicit append.
P: A shift register is a pair of terminals on the left and right edges of a loop. Whatever is wired to the right terminal in one iteration comes out of the left terminal in the next. It is the loop's memory: a running sum, the last reading, the error cluster, or the state of a state machine. A value wired into the left terminal from outside the loop initializes it; forgetting that initialization is a classic bug, because an uninitialized shift register keeps its value from the previous run of the VI.
P: Two patterns cover most lab programs. The state machine is a While Loop around a Case Structure, with an enum in a shift register that names the next state: Init, Soak, Sweep, Save, and Done for the temperature run of this chapter. Each case does one thing and writes the next state, which is the same structure as the switch-based state machines of Book 8, Chapter 12, drawn instead of typed. The producer-consumer pattern uses two While Loops connected by a queue. The producer acquires data at the pace of the hardware and enqueues it; the consumer dequeues and does the slow work, such as writing files or updating graphs. When the consumer stalls, the queue grows, and the acquisition keeps running.

WE: Worked Example 35.2: Sizing the queue
PROB: A DAQ task samples a channel at 10 kS/s, and the producer loop reads blocks of 1000 samples as 8-byte doubles. The consumer writes each block to a file on a network drive, which usually takes 20 ms but occasionally stalls for 3 s. How many blocks wait in the queue after a stall, and how much memory do they take? What would happen if the read and the write were in the same loop, given that NI-DAQmx sizes the input buffer of a continuous task at 10 kS for rates from 101 to 10 000 S/s unless told otherwise?
SOL: The producer makes 10 000/1000 = 10 blocks per second, so a 3 s stall leaves 30 blocks in the queue: 30 × 1000 × 8 = 240 000 bytes, 240 kB, which a PC holds without noticing. After the stall the consumer, at 20 ms per block, empties the queue at 50 blocks/s against 10 arriving, so it catches up in 30/(50 − 10) = 0.75 s. In a single loop the read waits for the write; the DAQmx buffer holds 10 000 samples, 1 s of data, so after 1 s of the 3 s stall the hardware overwrites samples that were never read and the read returns error −200279. The usual fix is producer-consumer; a larger DAQmx buffer only moves the limit.
H2: 35.4 Instruments: VISA, GPIB, USB, LAN, and SCPI
P: Chapter 34 covered SCPI, the text command language of bench instruments, and its use from Python and C#. LabVIEW uses the same layers. VISA is the vendor-neutral input/output library: a program opens a resource by name, writes and reads strings, and closes it, and the VISA library underneath, such as NI-VISA or Keysight VISA, handles the bus. The resource name says which bus: GPIB0::18::INSTR is address 18 on the first GPIB board; USB0::0x05E6::0x2450::04512345::INSTR is a USB Test and Measurement Class device with Keithley's vendor ID, the 2450's product ID, and its serial number; TCPIP0::192.168.1.50::hislip0::INSTR is a LAN instrument using the HiSLIP protocol, and TCPIP0::192.168.1.50::inst0::INSTR the older VXI-11.
P: GPIB, IEEE 488, is the old parallel instrument bus, still common in characterization labs because the instruments last for decades: up to 15 devices on one bus, a cable length limit of about 20 m in total, and solid, low-latency transfers. USB needs no extra card. LAN reaches across the building and suits instruments that stream a lot of data. The LabVIEW code is the same for all three; only the resource name changes.
P: A 2450-class SMU, a source-measure unit, sources voltage or current and measures current and voltage at the same time, in all four quadrants: up to 200 V or 1 A, 20 W, with current ranges from 10 nA to 1 A, at a list price of about US $7,900 in 2026. The SCPI commands for the sweep of this chapter, used in both Listing 35.1 and Listing 35.2, are *RST to reset; SENS:FUNC "CURR" and SENS:CURR:RANG:AUTO ON to measure current with autoranging; SENS:CURR:NPLC 1 for an integration time of one power-line cycle; SOUR:FUNC VOLT and SOUR:VOLT:RANG 20 to source voltage; SOUR:VOLT:ILIM to set the current limit, which protects the device; OUTP ON; then SOUR:VOLT and READ? at each point. The older 2400 speaks a different dialect for the same limit (SENS:CURR:PROT), so check the command set of the exact model.
P: An instrument driver wraps those strings in VIs: Initialize, Configure Source, Configure Measurement, Read, Close, each with a help page and range checks. NI's Instrument Driver Network and the instrument vendors publish drivers for most instruments, and a lab usually standardizes on them. Writing raw SCPI, as in this chapter, is still worth knowing, because a driver is only as good as its author and the manual's command reference is the final authority.
WE: Worked Example 35.3: Where a temperature run spends its time
PROB: The chuck under the device is moved from 25 °C to 75 °C and then to 125 °C. The device temperature follows each 50 K step with a time constant of 300 s. The VI calls the device soaked when the last 120 s of readings all lie within ±0.2 °C of the set point (Listing 35.4). How long does one step take to soak, and how does that compare with the 11.0 s of sweeping per temperature from Worked Example 35.1?
SOL: The remaining error after a step is 50 e^(−t/300) K. It falls to 0.2 K when e^(−t/300) = 0.2/50 = 0.004, so t = 300 × ln(250) = 300 × 5.52 = 1656 s. The 120 s window must then pass entirely inside the band, so the VI declares the soak at 1656 + 120 = 1776 s, 29.6 minutes. Two steps take 59.2 minutes, against 3 × 11.0 = 33 s of measuring. The measuring program is fast enough as it is; the throughput of a temperature lab is decided by the soak criterion and by how many devices sit on the chuck at once, not by the language the sweep is written in. A simulation of Listing 35.4 with this exponential gives the same 1776 s.

H2: 35.6 Extracting threshold voltage and on-resistance
P: A threshold voltage is a definition, not a single physical fact, and the lab must say which definition it uses. The linear-extrapolation method takes the Id-Vgs curve at a small Vds, finds the point of maximum transconductance gm = dId/dVgs, draws the tangent there, and reads where it crosses Id = 0; subtracting Vds/2 gives Vth. The constant-current method, used on datasheets, reports the gate voltage at which Id reaches a fixed value, often 250 µA or 1 mA, with the drain tied to the gate. The two give different numbers for the same part, and both are correct for their definitions; Chapter 7 compares the methods on the curve tracer. The on-resistance at a given gate voltage is the slope Vds/Id of the Id-Vds curve near the origin, measured with four-wire (Kelvin) connections so that the leads are not measured too.

WE: Worked Example 35.4: Threshold voltage by extrapolation
PROB: At 25 °C and Vds = 0.1 V, three neighboring points of the sweep are Vgs = 2.35, 2.40, and 2.45 V with Id = 4.8871, 6.0185, and 7.1465 mA, and gm is largest at 2.40 V. Find gm and Vth by linear extrapolation. The constant-current sweep with the drain tied to the gate reads 0.9796 mA at 2.16 V and 1.1383 mA at 2.17 V; find the 1 mA threshold.
SOL: gm = (7.1465 − 4.8871) mA/(2.45 − 2.35) V = 22.59 mS. The tangent through (2.40 V, 6.0185 mA) crosses zero at 2.40 − 6.0185/22.594 = 2.40 − 0.2664 = 2.1336 V. Subtracting Vds/2 = 0.05 V gives Vth = 2.084 V, as Listing 35.3 prints. For the constant-current threshold, interpolate: 2.16 + (1.0000 − 0.9796)/(1.1383 − 0.9796) × 0.01 = 2.16 + 0.0013 = 2.161 V. The same transistor has Vth = 2.084 V by one definition and 2.161 V by the other, 77 mV apart. A characterization report must name the method, the Vds, and the current, or the numbers cannot be compared with anyone else's.
WE: Worked Example 35.5: On-resistance, leads, and temperature
PROB: At Vgs = 10 V and 25 °C the drain current at Vds = 0.1 V is 89.82 mA. Find Ron. If the sweep had used two-wire connections with 50 mΩ in each lead, what would it report? At 125 °C the fit gives 1.689 Ω and Vth by extrapolation is 1.772 V. Find the temperature coefficients.
SOL: Ron = 0.1/0.08982 = 1.113 Ω, the same as the least-squares fit of Listing 35.3, since the curve is nearly straight below 0.1 V. With two-wire connections the SMU measures the leads in series, 2 × 0.050 = 0.100 Ω more: 1.213 Ω, 9 % high, enough to fail a good part against a 1.2 Ω limit. Four-wire sensing removes the lead drop. Over 100 K, Ron rises by a factor 1.689/1.113 = 1.52, and Vth falls by (1.772 − 2.084)/100 = −3.1 mV/K. Below the crossing point of 2.64 V, the current rises with temperature, because the falling threshold wins; above it, the current falls, because the falling mobility wins. Operating below that point in a linear power stage lets a hot spot take more current and get hotter, which is why paralleled MOSFETs in linear mode need care; Book 6 treats power devices in circuits.
H2: 35.7 Logging: TDMS and CSV
P: TDMS is NI's binary file format for measurement data. A file holds groups, a group holds channels, and the file, each group, and each channel carry properties: the device ID, the temperature, the NPLC setting, the instrument serial numbers, the operator. Writing is fast enough to stream data acquisition at high rates, and an index file next to the data file lets readers find channels without scanning. LabVIEW writes TDMS with TDMS Open, TDMS Set Properties, TDMS Write, and TDMS Close; DIAdem and an Excel add-in read it, and in Python the npTDMS package does.
P: CSV is slower and larger but readable by everything, including a text editor at three in the morning. For sweeps of a few hundred points it is entirely adequate, provided the metadata travels with the data: Listing 35.2 writes the device, temperature, NPLC, and a UTC time as comment lines above the column header. Many labs log both: TDMS from the LabVIEW station as the record, and CSV exports for analysis and for colleagues without LabVIEW. Whatever the format, the rule from Book 8, Section 21.3, holds: never plot from memory, only from the file.
H2: 35.8 DAQmx basics
P: NI-DAQmx is the driver and API for NI's data acquisition hardware, and the same concepts appear in LabVIEW, Python, C, and .NET. A task holds one or more channels of the same kind, such as voltage inputs, thermocouple inputs, or counter inputs. Timing sets the sample clock: a rate, finite or continuous acquisition, and the buffer size. Triggering starts the task on a digital edge or an analog level. Then the program starts the task, reads in blocks, and clears the task at the end. In LabVIEW these are DAQmx Create Channel, DAQmx Timing, DAQmx Trigger, DAQmx Start Task, DAQmx Read, and DAQmx Clear Task, wired in a row with the task and error wires; the nidaqmx Python package has the same structure in Listing 35.4.
P: The thermocouple in this chapter measures the device temperature near the socket, because the chuck's own sensor reports the chuck, not the part. Thermocouple inputs need cold-junction compensation, which the module provides with a built-in sensor, and they are slow, typically a few to a few tens of samples per second, so the soak loop averages one second of readings at a time.

H2: 35.9 TestStand: sequences, limits, and reports
P: A characterization lab measures a few parts in great detail; a production line measures every part quickly against limits and keeps a record of each one. TestStand is built for the second job. A sequence file holds sequences of steps in three groups: Setup, Main, and Cleanup, and Cleanup runs even when a step fails or an operator aborts, which is where outputs are switched off. Each step calls a code module through an adapter, for LabVIEW, Python, .NET, C and C++ libraries, or another sequence, and has a type: Pass/Fail Test, Numeric Limit Test, Multiple Numeric Limit Test, String Value Test, or Action.
P: Around the sequence sits a process model, which does what every production test needs and no single test should contain: asking for the serial number, running the sequence for each part, generating the report in XML, HTML, or ATML format, and logging results to a database. The Sequential model tests one part at a time, the Parallel model runs independent test sockets, and the Batch model synchronizes sockets that share a step, such as a chamber temperature. The operator sees an operator interface, not the development environment, and TestStand's user management decides who may change limits.

WE: Worked Example 35.6: From characterization to production
PROB: Characterization took 465 readings per part and temperature. Production needs only four numbers: gate leakage at Vgs = 5 V, Vth at 1 mA with the drain tied to the gate, Id at Vgs = 5 V and Vds = 0.1 V, and Ron at Vgs = 10 V. H2: 35.10 Crossing languages
P: Few labs are pure. LabVIEW calls Python through three functions: Open Python Session (with the Python version, or the path to a virtual environment's interpreter), Python Node (module path, function name, inputs, and a return type), and Close Python Session. Numeric arrays arrive as lists by default and clusters as tuples, so a function such as vth_max_gm in Listing 35.3 needs no changes. LabVIEW 2026 Q3, the current release in October 2026, supports Python 3.9 to 3.14, and the bitness of Python must match that of LabVIEW. Calling .NET uses the Constructor Node to create an object, Property Nodes to read and write its properties, and Invoke Nodes to call its methods; current versions support .NET Framework 4.x and, since LabVIEW 2025 Q1, .NET 8. A C library is called through the Call Library Function Node.
P: The other direction works too. LabVIEW's Application Builder, part of the Professional edition, builds a VI into a stand-alone application, a shared library (a DLL that Python can load with ctypes or C# with P/Invoke), or a .NET assembly that C# can reference (called a .NET Interop Assembly before LabVIEW 2025 Q1). The target PC then needs the free LabVIEW Run-Time Engine of the same version. Often the loosest coupling is the best: the LabVIEW station runs as its own program, and Python or C# talks to it through files, a TCP socket, or a database. TestStand is the meeting point for all of them, since one sequence can call LabVIEW, Python, and .NET steps side by side.

H2: 35.11 Licenses and cost
P: LabVIEW is commercial software. It comes in Base, Full, and Professional editions, and as part of the LabVIEW+ Suite, which adds TestStand, DIAdem, FlexLogger, and other tools; licenses are sold as annual subscriptions and as perpetual licenses. As a guide, European reseller list prices in 2026 were about €3,000 per year for a LabVIEW Professional subscription and about €4,500 per year for the LabVIEW+ Suite, before tax; check current prices for your country before budgeting. TestStand needs a development license for each engineer who writes sequences and a deployment license for each station that runs them. The drivers, NI-VISA and NI-DAQmx, and the LabVIEW Run-Time Engine are free downloads. LabVIEW is released twice a year, in the first and third quarters, and versions are named by year and quarter, such as 2026 Q3.
P: For hobbyists there is the LabVIEW Community Edition. In October 2026 NI's terms make it free for personal, non-commercial, non-industrial use: home projects, open-source projects, studying, and keeping skills sharp. It has the capabilities of the Professional edition and includes the LINX toolkit for the Raspberry Pi, BeagleBoard, and Arduino. The license runs for one year and is renewed from your NI account. It may not be used for anything that earns money, directly or indirectly, at a place of business, or for teaching and research at degree-granting institutions, which have academic licenses. On macOS, the Community Edition is the only edition from LabVIEW 2025 Q3 on. These terms have changed before; read NI's current Community Edition usage page before you rely on them.
H2: 35.12 Choosing the tool
P: There is no single right answer, but there are honest ones. LabVIEW wins where the lab already owns NI hardware and LabVIEW code, where technicians need a usable front panel today, and where data acquisition and parallel instruments are the core of the job. TestStand wins on a production line where many parts, sockets, operators, and reports must be managed, whatever language the steps are written in. Python with PyVISA and PyMeasure wins for one engineer or a small team, for analysis and plotting, for continuous integration, and when the budget for licenses is zero; PyMeasure even has a ready-made class for the 2450. C# wins when the tool becomes a product: a polished Windows application for customers or a test bench that a software team will maintain for a decade.
P: The weaknesses matter as much. LabVIEW's graphical files do not diff or merge like text, so code review and large teams need extra tools and discipline. TestStand is a sequencer, not an analysis or GUI tool. Python operator GUIs and packaging take more work than a front panel. C# has fewer ready-made instrument examples than Python. Many labs end up with a mix: LabVIEW at the characterization bench, Python for analysis and reports, TestStand on the line calling modules in all three.

KEY: In LabVIEW, wires decide the order and unconnected code runs in parallel; use the error wire to sequence instrument calls, shift registers for loop state, state machines for procedures, and producer-consumer for acquisition. Name the extraction method with every threshold you report, measure resistance with four wires, and let the soak criterion, not the language, set the schedule.
MIS: The block diagram runs from left to right. It does not; it runs in dataflow order, and two nodes with no wire between them have no defined order. A VI that turns the SMU output off in a node placed at the right edge, but not wired after the last reading, can switch the output off before the reading is made, on some runs and not on others. Wire the error cluster through every instrument call, and the order is fixed.
AI: AI assistants work in text, and LabVIEW code is a picture, so their help with LabVIEW is indirect: they describe which functions to place and how to wire them, and they write the SCPI strings, the Python and C# modules that LabVIEW calls, and TestStand expressions. Recent LabVIEW and TestStand versions include a built-in assistant that can generate simple VIs and sequences from a prompt; review what it produces the way you would review a colleague's work. The dangerous mistakes are the ones that reach the hardware: an assistant that mixes the 2400 and 2450 command sets, or that omits the current limit, can destroy the part on the first run. Give the exact instrument model, ask for every command to be listed with its purpose, check each against the reference manual, and run the sequence first with the output off or on a resistor.
JOB: On the Job: In a semiconductor characterization lab, the sweep VI is the measurement of record. Its numbers become the minimum and maximum values in a datasheet, so the lab treats it like a calibrated instrument: the VI and its limits are under version control, each data file records the VI version, the instrument serial numbers, and their calibration dates, and a golden unit, a part kept only for this purpose, is measured at the start of every shift and must repeat within its control limits. When the production tester and the bench disagree, the correlation study between them is a project of its own, and the first question is always whether both used the same definition of threshold voltage.
BENCH: Before you trust a new sweep setup, measure a four-terminal precision resistor of about 1 Ω in place of the transistor and check that the program reports its value within the SMU's specified accuracy. Then measure the transistor. A MOSFET on long SMU cables can oscillate in the hundreds of megahertz, which shows up as noisy or impossible currents near the threshold; a resistor of about 100 Ω in series with the gate, close to the socket, usually stops it. Check that no reading hit the current limit, and record the limit status with the data.
H2: Practice
PP: 1. (Core) What decides the order in which nodes run on a block diagram, and what happens to two nodes with no wire between them?
PP: 2. (Core) Write the VISA resource names for a 2450 at GPIB address 18 on the first GPIB board, on USB with serial number 04512345, and on the LAN at 192.168.1.50 using HiSLIP.
PP: 3. (Core) A sweep runs from −1 V to 4 V in 25 mV steps, including both ends. How many points does it have?
PP: 4. (Core) Which LabVIEW structure carries a value from one loop iteration to the next, and how do you use it to keep the running mean of the readings?
PP: 5. (Extension) At 125 °C and Vds = 0.1 V the sweep reads Id = 3.9554, 4.6677, and 5.3800 mA at Vgs = 2.10, 2.15, and 2.20 V, with maximum gm at 2.15 V. Find gm and Vth by linear extrapolation, and the threshold's temperature coefficient against the 25 °C value of 2.084 V.
PP: 6. (Extension) One temperature of Listing 35.2 produces 465 rows of four values. How many bytes do the values take as 8-byte doubles in a binary file such as TDMS? The three CSV files of Listing 35.2 for one temperature total 25 371 bytes. What is the ratio, and how much space do 200 parts at three temperatures take in each format?
PP: 7. (Extension) A DAQ task samples at 50 kS/s and the producer reads 5000-sample blocks of doubles. The file writer can stall for up to 4 s. How many blocks and how many bytes can wait in the queue? Would a single loop survive the stall with the default DAQmx buffer, which is 100 kS for rates from 10 001 S/s to 1 MS/s?
PP: 8. (Challenge) A start-up must characterize three new MOSFET variants over temperature in the next two months and then hand a test to a contract manufacturer that will test 2000 parts per day in two shifts of 7.5 hours. The team has two engineers who know Python and no NI hardware. Each production test needs four readings of 23.7 ms and 6 s of handling. Recommend the tools for characterization and for production, compute how many test stations are needed, and say what would change your recommendation.
ANS: 1. Dataflow decides: a node runs when all its inputs have arrived, and its position on the page does not matter. Two nodes with no wire between them have no defined order and may run in parallel; to force an order, wire the error cluster (or another output) from one to the other. The usual mistake is to assume left-to-right order because the diagram reads that way.
ANS: 2. GPIB0::18::INSTR; USB0::0x05E6::0x2450::04512345::INSTR; TCPIP0::192.168.1.50::hislip0::INSTR. The usual mistake is to write the USB vendor and product IDs in decimal (1510 and 9296) instead of the hexadecimal form that VISA lists.
ANS: 3. (4 − (−1))/0.025 = 200 steps, so 201 points. The usual mistake is to answer 200, counting the steps instead of the points; the For Loop's N must be 201.
ANS: 4. A shift register. Initialize the left terminal with 0 from outside the loop, add each reading to the value from the left terminal, wire the sum to the right terminal, and divide by i + 1 for the mean. The usual mistake is to leave the shift register uninitialized, so that the sum continues from the previous run of the VI.
ANS: 5. gm = (5.3800 − 3.9554) mA/0.10 V = 14.246 mS. The tangent crosses zero at 2.15 − 4.6677/14.246 = 2.15 − 0.3277 = 1.8223 V, and Vth = 1.8223 − 0.05 = 1.772 V. The coefficient is (1.772 − 2.084)/(125 − 25) = −3.1 mV/K. The usual mistake is to forget the Vds/2 correction, which reports 1.822 V and makes every threshold 50 mV high.
ANS: 6. 465 × 4 × 8 = 14 880 bytes, so CSV takes 25 371/14 880 = 1.7 times as much. For 200 parts at three temperatures, 600 runs: about 8.9 MB of binary values (plus a small amount of TDMS metadata) against 15.2 MB of CSV. Both are small for a modern disk; the reasons to choose TDMS are speed for streaming and structured properties, not this size. The usual mistake is to choose the format on size alone, at sizes where it does not matter.
ANS: 7. 50 000/5000 = 10 blocks per second, so a 4 s stall leaves 40 blocks: 40 × 5000 × 8 = 1 600 000 bytes, 1.6 MB, in the queue. A single loop would not survive: the default buffer of 100 kS holds 100 000/50 000 = 2 s, so after 2 s of the stall unread samples are overwritten and the read fails. The usual mistake is to enlarge the DAQmx buffer and stop there; it works until the next, longer stall, while producer-consumer keeps the acquisition independent of the writer.
ANS: 8. For characterization, Python with PyVISA (or PyMeasure's 2450 class) and the structure of Listings 35.2 and 35.3: the team knows it, it costs nothing, and the bench needs only two SMUs and a chuck, all with SCPI. For production, a test of 4 × 23.7 ms + 6 s = 6.1 s per part gives 2 × 7.5 × 3600/6.1 = about 8850 parts per day per station, so one station covers 2000 parts with room for retests and downtime; a second station is worth having as a spare. The test should be a small, version-controlled Python or C# program with limits in a configuration file, unless the contract manufacturer already runs TestStand, in which case the Python modules become TestStand steps through its Python adapter and the manufacturer's reports and databases come for free. The recommendation changes if NI data acquisition hardware is needed, if the manufacturer standardizes on LabVIEW, or if many product variants and sockets make TestStand's process models worth their license cost. The usual mistake is to pick the tool before counting the readings: the measurement time is about 1.6 % of the test time here, so handling, not software speed, sets the number of stations.
