## Repository-boundary assessment

The shared repository increases the blast radius: `git status` and commits span unrelated titles, and a single broad commit could mix book work. It did not itself create the status rows. The main source of confusion is that the D: checkout is on a heavily divergent branch (142 ahead and 601 behind current `main`), with historical path aliases and local files mixed together. Separate repositories by series/workflow boundary would make future status, review, and commits easier to isolate. Keep tightly related books and their shared assets/builders together (for example, the Step Stories books); keep genuinely shared author guidance in a small separate workspace or copy the relevant guidance into each series repo. Do not migrate until this reconciliation is complete and a path/history map is ready. Extract from a clean `main` snapshot with history-preserving path filters, verify each new repo, and retain the current shared repo as a read-only rollback archive until validation is complete.
